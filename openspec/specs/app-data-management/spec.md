# app-data-management Specification

## Purpose

Управление данными приложения: экспорт всех упражнений и записей о
тренировках в резервную копию JSON, восстановление слиянием из резервной
копии и удаление всех данных с возвратом к стандартному набору упражнений.

## Requirements

### Requirement: Экран «Данные приложения» — не таб

Экран «Данные приложения» (переход на него — требование «MoreScreen has
app data button» спеки `more-screen`) SHALL NOT быть табом: нижняя панель
навигации на нём скрыта, в заголовке SHALL быть стрелка назад,
возвращающая на предыдущий экран («Ещё»).

#### Scenario: Нижняя панель скрыта

- **WHEN** экран «Данные приложения» открыт
- **THEN** нижняя панель навигации не отображается

#### Scenario: Возврат назад

- **WHEN** пользователь нажимает стрелку назад в заголовке
- **THEN** происходит возврат на экран «Ещё», нижняя панель навигации
  снова видна

### Requirement: Создание резервной копии

Кнопка «Создать резервную копию» / "Create backup" SHALL выгружать все
упражнения, все категории и все записи о тренировках в JSON-файл через
системный выбор места сохранения (SAF) с mime-типом `application/json`.
Кнопка SHALL быть скрыта, если в приложении нет данных для экспорта, и
SHALL быть недоступна, пока выполняется любая из трёх операций. Результат
— Toast об успехе или ошибке.

#### Scenario: Успешный экспорт

- **WHEN** в приложении есть записи и пользователь выбирает место
  сохранения
- **THEN** в выбранное место записывается JSON-файл резервной копии
- **AND** показывается Toast об успешном создании резервной копии
- **AND** предлагаемое имя файла — `myworkouts-backup-<yyyy-MM-dd>.json`,
  где `<yyyy-MM-dd>` — текущая дата

#### Scenario: Нет данных — кнопки скрыты

- **WHEN** в приложении нет ни записей о тренировках, ни кастомных
  упражнений, ни кастомных категорий (только стандартные наборы)
- **THEN** кнопки «Создать резервную копию» и «Удалить все данные» скрыты
- **AND** кнопка «Восстановить из резервной копии» остаётся видимой
- **AND** критерий «нет данных»: ни одной записи, ни одного кастомного
  упражнения и ни одной кастомной категории (стандартный набор упражнений
  и категорий предзаполняется всегда и сам по себе данными пользователя не
  считается; правки стандартных упражнений данными пользователя не
  считаются)

#### Scenario: Только пользовательские упражнения — экспорт доступен

- **WHEN** записей нет, но есть хотя бы одно кастомное упражнение
- **THEN** кнопка «Создать резервную копию» видима
- **AND** экспорт создаёт файл со списком упражнений и пустым массивом
  записей

#### Scenario: Только кастомная категория — экспорт доступен

- **WHEN** записей и кастомных упражнений нет, но есть хотя бы одна
  кастомная категория
- **THEN** кнопка «Создать резервную копию» видима
- **AND** экспорт создаёт файл с категориями и пустыми массивами упражнений
  и записей

#### Scenario: Кнопка недоступна во время экспорта

- **WHEN** экспорт выполняется
- **THEN** кнопка «Создать резервную копию» недоступна для нажатия
- **AND** прогресс-индикатор не показывается

### Requirement: Формат файла резервной копии

Резервная копия SHALL быть JSON-объектом
`{ "version": 1, "exercises": [...], "categories": [...], "entries": [...],
"settings": {...} }`, где `version` — версия формата. Каждый элемент
массивов SHALL содержать поля соответствующей сущности (см. сценарии);
блок `settings` SHALL писаться всегда. Идентификаторы строк базы данных и
поле `modifiedAt` в файле SHALL NOT храниться. Файл SHALL быть
отформатирован человекочитаемо (с отступами).

#### Scenario: Структура файла

- **WHEN** резервная копия создана
- **THEN** файл начинается с объекта, содержащего `"version": 1`, массивы
  `exercises`, `categories`, `entries` и блок `settings`
- **AND** записи ссылаются на упражнения по имени, упражнения — на
  категории по имени, без идентификаторов БД
- **AND** связь «запись → упражнение» выражается именем упражнения
  (`exerciseName` → `name`), связь «упражнение → категория» — именем
  категории (`exercises[].category` → `categories[].name` либо категории
  текущей БД); идентификаторы строк базы данных в файле не хранятся

#### Scenario: Блок настроек в файле

- **WHEN** резервная копия экспортируется при выключенной вкладке «Рекорды»
  и последней вкладке «Активность»
- **THEN** блок `settings` содержит `overviewTabVisibility` с
  `"RECORDS": false` и `lastOverviewTab = "ACTIVITY"`
- **AND** файл без блока `settings` (старый бэкап) импортируется успешно
  без изменения настроек устройства

#### Scenario: Категории в файле

- **WHEN** резервная копия экспортируется при наличии кастомной категории
  «Спина» с `colorArgb = 0xFF4E6EF2`
- **THEN** массив `categories` содержит все категории БД (активные и
  архивные), включая элемент с `"name": "Спина"`, `"colorArgb"` — Int ARGB
  этой категории, `"isArchived": false`, и пять стандартных категорий

#### Scenario: Старый файл без категорий импортируется

- **WHEN** импортируется валидный файл версии 1 без массива `categories`
  (бэкап, сделанный до введения поля)
- **THEN** импорт завершается успешно
- **AND** упражнения резолвят категории по текущей БД; упражнение с
  категорией, отсутствующей в БД, пропускается
- **AND** массив `categories` — обратно совместимое расширение формата
- **AND** чтение нового файла старой версией приложения вне скоупа этого
  изменения и уже покрыто гарантией «Неизвестные поля игнорируются»
  (требование «Обработка ошибок восстановления»)

#### Scenario: Опциональные поля

- **WHEN** у упражнения или записи нет комментария/веса/длительности
- **THEN** соответствующее поле отсутствует или равно `null` в файле

#### Scenario: Номер иконки в файле

- **WHEN** резервная копия экспортируется
- **THEN** каждый элемент `exercises` содержит поле `iconNumber`:
  целое число либо `null`, если у упражнения нет иконки
  (поле пишется всегда, даже как `null`; «(опционально)» в списке —
  про допустимость старых файлов при импорте)

#### Scenario: Старый файл без номера иконки импортируется

- **WHEN** импортируется валидный файл версии 1, элементы `exercises`
  которого не содержат `iconNumber` (бэкап, сделанный до введения поля)
- **THEN** импорт завершается успешно
- **AND** упражнениям из файла присваивается `iconNumber = null`

#### Scenario: Признак архивации в файле

- **WHEN** резервная копия экспортируется
- **THEN** каждый элемент `exercises` и `categories` содержит поле
  `isArchived`: `true` — если сущность архивная, `false` — если активная
  (поле пишется всегда)
- **AND** поле `isArchived` пишется в файл всегда как `true` или `false`,
  SHALL NOT отсутствовать и SHALL NOT быть `null`

#### Scenario: Старый файл без признака архивации импортируется

- **WHEN** импортируется валидный файл версии 1, элементы `exercises`
  которого не содержат `isArchived` (бэкап, сделанный до введения поля)
- **THEN** импорт завершается успешно
- **AND** упражнениям из файла присваивается `isArchived = false`

#### Scenario: Поля элементов exercises

- **WHEN** в файл пишется элемент `exercises`
- **THEN** он содержит поля упражнения: `name`, `category` (имя категории
  — String), `measuredBy`, `isCustom`, `comment` (опционально),
  `iconNumber` (опционально), `createdAt`, `isArchived`

#### Scenario: Поля элементов categories

- **WHEN** в файл пишется элемент `categories`
- **THEN** он содержит поля категории: `name` (String), `colorArgb` (Int),
  `isArchived` (Boolean, пишется всегда как `true`/`false`)
- **AND** поле `isCustom` в файл SHALL NOT писаться (значение из файла
  игнорируется при импорте — файл недоверенный)

#### Scenario: Поля элементов entries

- **WHEN** в файл пишется элемент `entries`
- **THEN** он содержит поля записи: `exerciseName`, `date`, `sets`,
  `reps` (опционально), `weightKg` (опционально), `durationSec`
  (опционально), `comment` (опционально), `createdAt`

#### Scenario: Состав блока settings

- **WHEN** блок `settings` пишется в файл
- **THEN** он содержит настройки видимости вкладок обзора:
  `overviewTabVisibility` (карта имя-вкладки → Boolean) и
  `lastOverviewTab` (String)
- **AND** контракт включения в копию и применения при восстановлении —
  канон спеки `overview-screen` (требование «Экран настроек видимости
  вкладок»)
- **AND** файл без блока `settings` (бэкапы до его введения) SHALL
  оставаться валидным — при импорте состояние настроек SHALL NOT меняться

#### Scenario: modifiedAt не хранится

- **WHEN** резервная копия экспортируется
- **THEN** поле `modifiedAt` в файле не хранится
- **AND** восстановленная запись получает `modifiedAt`, равный моменту
  импорта

#### Scenario: Типы полей

- **WHEN** резервная копия экспортируется
- **THEN** типы полей: `version` — Int; `date` и `createdAt` — Long
  (миллисекунды эпохи); `sets`, `reps`, `durationSec`, `iconNumber`,
  `colorArgb` — Int; `weightKg` — Double; `isCustom`, `isArchived` —
  Boolean; строки (`name`, `category`, `measuredBy`, `exerciseName`,
  `comment`) — String
- **AND** экспорт SHALL писать поля строго указанных типов

#### Scenario: Семантика опциональных полей

- **WHEN** в списке полей указано «(опционально)»
- **THEN** поле может отсутствовать или быть `null`; при наличии значение
  иного типа делает файл ошибочным

#### Scenario: Толерантность декодера импорта

- **WHEN** импортируется файл, где числовое значение записано в строковом
  литерале (`"sets": "4"`) или JSON-целое — в поле `weightKg`
  (`"weightKg": 75`) (обратная совместимость с файлами сторонних
  редакторов)
- **THEN** значения SHALL приниматься при импорте как значение указанного
  типа

#### Scenario: Версии формата

- **WHEN** выполняется экспорт или импорт резервной копии
- **THEN** экспорт SHALL писать версию `1`
- **AND** импорт SHALL принимать `1` и `2` — файлы с меткой `2` создаёт
  код существующих релизов, они остаются читаемыми (Design Decision 9)

### Requirement: Восстановление из резервной копии слиянием

Кнопка «Восстановить из резервной копии» / "Restore from backup" SHALL
открывать системный выбор файла (SAF) без ограничения mime-типа.
Выбранный файл SHALL сливаться с текущими данными: ничего не
перезаписывается, добавляется только недостающее. Дедупликация:
упражнения — по имени (без учёта регистра), категории — по
`name.trim().lowercase()`, записи — по содержимому. Повторный импорт
того же файла SHALL быть идемпотентным. Результат — Toast об успехе или
ошибке.

#### Scenario: Успешное слияние

- **WHEN** выбран корректный файл резервной копии
- **THEN** категории и упражнения из файла, которых нет в БД, добавляются
- **AND** записи из файла, дубликатов которых нет, добавляются
- **AND** существующие данные не изменяются, кроме архивации по
  одностороннему правилу
- **AND** показывается Toast об успешном восстановлении

#### Scenario: Дубликаты пропускаются

- **WHEN** категория или упражнение с тем же именем уже есть в БД
- **THEN** новая сущность не создаётся
- **AND** когда запись с тем же содержимым уже есть в базе
- **THEN** дубликат записи не вставляется
- **AND** записи дедуплицируются по содержимому (имя упражнения, дата,
  подходы, повторы, вес, длительность, комментарий)

#### Scenario: Категория из файла создаётся при отсутствии

- **WHEN** в файле есть категория «Спина», которой нет в БД
- **THEN** категория вставляется с `colorArgb` и `isArchived` из файла
  AND `isCustom = true`
- **AND** стандартные категории всегда есть в БД и дедупятся

#### Scenario: Упражнение с неизвестной категорией пропускается

- **WHEN** упражнение из файла ссылается на категорию, которой нет ни
  в файле, ни в текущей БД
- **THEN** это упражнение пропускается, остальные сущности файла
  импортируются (по аналогии с записями без упражнения)
- **AND** записи, ссылающиеся на это упражнение по имени, тоже
  пропускаются

#### Scenario: Архивация существующей категории из файла применяется

- **WHEN** категория из файла дедуплицируется по имени с существующей
  активной AND в файле у неё `isArchived = true`
- **THEN** существующая категория перемещается в архив

#### Scenario: Разархивация существующей категории из файла не выполняется

- **WHEN** категория из файла дедуплицируется с существующей архивной
  AND в файле у неё `isArchived = false`
- **THEN** существующая категория остаётся в архиве

#### Scenario: Цвет существующей категории не меняется

- **WHEN** категория из файла дедуплицируется с существующей
- **THEN** существующая категория остаётся со своим прежним `colorArgb`

#### Scenario: Номер иконки вставленного упражнения сохраняется

- **WHEN** упражнение из файла вставляется в каталог (имени нет в каталоге)
- **THEN** вставленное упражнение получает `iconNumber` из файла

#### Scenario: Номер иконки существующего упражнения при дедупликации не меняется

- **WHEN** упражнение из файла дедуплицируется по имени с существующим
- **THEN** существующее упражнение остаётся со своим прежним `iconNumber`

#### Scenario: Запись без упражнения пропускается

- **WHEN** запись ссылается на имя упражнения, которого нет ни в файле,
  ни в текущем каталоге
- **THEN** эта запись пропускается, остальные записи файла импортируются

#### Scenario: Признак архивации вставленного упражнения сохраняется

- **WHEN** упражнение из файла с `isArchived = true` вставляется в каталог
- **THEN** вставленное упражнение получает `isArchived = true` и попадает
  в архив

#### Scenario: Архивация существующего упражнения из файла применяется

- **WHEN** упражнение из файла дедуплицируется по имени с существующим
  AND в файле у него `isArchived = true` AND существующее упражнение
  активно
- **THEN** существующее упражнение перемещается в архив

#### Scenario: Разархивация существующего упражнения из файла не выполняется

- **WHEN** упражнение из файла дедуплицируется по имени с существующим
  AND в файле у него `isArchived = false` AND существующее упражнение
  архивное
- **THEN** существующее упражнение остаётся в архиве (значение из файла
  игнорируется)

#### Scenario: Идемпотентность повторного импорта

- **WHEN** один и тот же файл импортируется дважды
- **THEN** после второго импорта категории, упражнения и записи не
  дублируются

#### Scenario: Связь упражнения с категорией по имени

- **WHEN** упражнение из файла вставляется в БД
- **THEN** связь с категорией восстанавливается по имени: используется
  существующая в БД категория либо вставленная из файла
- **AND** при дедупликации категории по имени существующая категория не
  изменяется, кроме одностороннего применения архивации (симметрично
  правилу упражнений)

#### Scenario: isCustom вставленного упражнения

- **WHEN** упражнение из файла вставляется в каталог
- **THEN** оно получает `isCustom = true`: значение `isCustom` из файла
  игнорируется (файл недоверенный)

#### Scenario: Невалидные записи пропускаются

- **WHEN** запись из файла не проходит валидацию (например, количество
  подходов меньше 1 или несовместимый с типом измерения упражнения набор
  полей)
- **THEN** запись пропускается без провала всего импорта

#### Scenario: Без диалога подтверждения

- **WHEN** пользователь выбирает файл для восстановления
- **THEN** диалог подтверждения импорта не показывается: merge только
  добавляет и архивирует

### Requirement: Обработка ошибок восстановления

Битый или несовместимый файл SHALL приводить к Toast с обобщённым
локализованным сообщением об ошибке (ru/en); технические детали ошибки
пользователю SHALL NOT показываться — они попадают в лог. Данные
приложения SHALL NOT меняться. Ошибочными считаются: нечитаемый JSON;
отсутствие или неверный тип полей `version`, `exercises`, `entries`;
неподдерживаемая версия формата (полный перечень — в сценариях).

#### Scenario: Битый JSON

- **WHEN** выбран файл, не являющийся корректным JSON
- **THEN** показывается Toast с ошибкой
- **AND** данные приложения не изменились

#### Scenario: Неподдерживаемая версия формата

- **WHEN** файл содержит `"version"`, отличный от поддерживаемых версий
  (поддерживаемые — `1` и `2`)
- **THEN** показывается Toast с ошибкой о несовместимом файле
- **AND** данные приложения не изменились

#### Scenario: Ошибочные элементы массивов

- **WHEN** элемент массива `exercises`/`entries` не содержит обязательных
  полей или содержит значение неверного типа
- **THEN** файл считается ошибочным

#### Scenario: Неизвестное значение measuredBy

- **WHEN** в файле встречается неизвестное значение `measuredBy` где-либо
- **THEN** файл считается ошибочным

#### Scenario: Неизвестные поля игнорируются

- **WHEN** объекты файла содержат поля, не входящие в формат резервной
  копии
- **THEN** импорт выполняется успешно, неизвестные поля игнорируются

#### Scenario: Категория упражнения с произвольной строкой

- **WHEN** файл содержит упражнение с `category = "Старая категория"`,
  которой нет ни в `categories` файла, ни в БД
- **THEN** файл НЕ отвергается
- **AND** упражнение пропускается, остальной импорт продолжается
- **AND** пропуск такого упражнения определён требованием «Восстановление
  из резервной копии слиянием»

#### Scenario: Ошибочные поля categories

- **WHEN** у элемента `categories` отсутствует или имеет неверный тип поле
  `name` (если массив присутствует), либо неверный тип `colorArgb`/
  `isArchived`
- **THEN** файл считается ошибочным

### Requirement: Удаление всех данных

Кнопка «Удалить все данные» / "Delete all data" SHALL быть стилизована в
цвет ошибки и SHALL открывать `AlertDialog` подтверждения. При
подтверждении удаляются все записи о тренировках и все упражнения, после
чего каталог SHALL содержать стандартный набор упражнений. Настройки
приложения SHALL NOT меняться, результат — Toast.

#### Scenario: Подтверждение удаления

- **WHEN** пользователь подтверждает удаление в диалоге
- **THEN** все записи удалены
- **AND** каталог содержит стандартный набор упражнений и не содержит
  пользовательских
- **AND** набор тот же, что предзаполняется при первом создании базы
- **AND** настройки приложения (тема, динамические цвета) не меняются
- **AND** показывается Toast об успешном удалении

#### Scenario: Отмена удаления

- **WHEN** пользователь отменяет диалог подтверждения
- **THEN** данные не удаляются, диалог закрывается

#### Scenario: Кнопки скрыты после удаления

- **WHEN** удаление всех данных завершилось
- **THEN** кнопки «Создать резервную копию» и «Удалить все данные» скрыты
  реактивно, без перезапуска экрана

#### Scenario: Кнопки недоступны во время удаления

- **WHEN** удаление выполняется
- **THEN** кнопки недоступны

### Requirement: Результаты операций и занятость кнопок

Любая операция (экспорт, восстановление, удаление) во время выполнения
SHALL делать недоступными все три кнопки операций; параллельные
операции SHALL NOT запускаться. Результат операции
SHALL показываться Toast-сообщением ровно один раз: экран сбрасывает
сообщение после показа. Во время операции прогресс-индикаторы SHALL NOT
показываться.

#### Scenario: Toast показывается один раз

- **WHEN** операция завершается успехом или ошибкой
- **THEN** Toast с сообщением показывается один раз и не повторяется при
  следующей recomposition экрана

#### Scenario: Во время операции недоступны все кнопки

- **WHEN** выполняется импорт
- **THEN** кнопки экспорта, восстановления и удаления недоступны
- **AND** после завершения операции кнопки снова доступны

### Requirement: Локализация экрана ru/en

Все строки экрана SHALL существовать в `res/values/strings.xml` (русские
значения по умолчанию) и `res/values-en/strings.xml` (английские):
заголовок, подписи трёх кнопок, текст и кнопки диалога удаления, тосты
успеха трёх операций и обобщённые тексты ошибок четырёх видов (экспорт,
импорт, несовместимый файл, удаление) — требование «Обработка ошибок
восстановления».

#### Scenario: Русская локаль

- **WHEN** локаль устройства `ru`
- **THEN** заголовок — «Данные приложения», кнопки — «Создать резервную
  копию», «Восстановить из резервной копии», «Удалить все данные»

#### Scenario: Английская локаль

- **WHEN** локаль устройства `en`
- **THEN** заголовок — "App data", кнопки — "Create backup", "Restore
  from backup", "Delete all data"
