# workouts-main-screen Specification

## Purpose

Главный экран тренировок: каркас со `TopAppBar`, заголовком и FAB,
открывающим экран создания записи о выполнении, с локализованными
ru/en подписями и корректной обработкой системных отступов.

## Requirements
### Requirement: MainScreen Scaffold with TopAppBar

`MainScreen` SHALL be a `@Composable fun MainScreen(viewModel: MainViewModel, onAddEntryClick: () -> Unit, modifier: Modifier = Modifier)` annotated with `@OptIn(ExperimentalMaterial3Api::class)`. Its `Scaffold` SHALL contain `topBar = { TopAppBar(title = { Text(stringResource(R.string.workouts_title)) }) }`. The `Scaffold` body SHALL display the list of workout entries or, when there are no entries, the empty-state placeholder (см. «Пустое состояние списка записей»).

#### Scenario: MainScreen renders with localized title

- **WHEN** `MainScreen` is composed with the Russian locale active
- **THEN** the `TopAppBar` displays "Тренировки"
- **AND** the `Scaffold` body displays the list of entries or the empty-state placeholder

### Requirement: Список записей на главном экране

Тело главного экрана SHALL отображать записи о выполнении в виде
прокручиваемого списка. Записи SHALL быть упорядочены по дате/времени
записи убыванием: новые сверху, старые ниже. Каждая строка SHALL быть
переиспользуемым компонентом: слева — название упражнения, справа с
выравниванием по правому краю — значение подходов и повторов/длительности.
Разделитель между названием и значением (запятая и т.п.) SHALL NOT
отображаться.

#### Scenario: Записи отображаются после сохранения

- **WHEN** пользователь сохранил запись на экране создания и вернулся
  на главный экран
- **THEN** новая запись отображается в списке первой

#### Scenario: Новые записи выше старых

- **WHEN** в списке есть записи с разными датами
- **THEN** запись с более поздней датой/временем расположена выше записи
  с более ранней

#### Scenario: Строка записи: название слева, значение справа

- **WHEN** список отображает запись
- **THEN** название упражнения выровнено по левой части строки
- **AND** значение (подходы, повторы/длительность) выровнено по правой
  части строки без разделителя-запятой между ними

### Requirement: Формат значения записи

Значение в строке записи SHALL формироваться по количеству подходов:
при нескольких подходах — «подходы × значение» (например «4 х 10»), при
одном подходе — только значение (например «10»). Для упражнений на время
формат тот же, значение — длительность записи (примеры — в сценариях
ниже).

#### Scenario: Несколько подходов с повторами

- **WHEN** запись содержит 4 подхода по 10 повторов
- **THEN** значение отображается как «4 х 10»

#### Scenario: Один подход с повторами

- **WHEN** запись содержит 1 подход по 10 повторов
- **THEN** значение отображается как «10»

#### Scenario: Несколько подходов с длительностью

- **WHEN** запись содержит 3 подхода по 20 секунд
- **THEN** значение отображается как «3 х 20»

#### Scenario: Один подход с длительностью

- **WHEN** запись содержит 1 подход длительностью 20 секунд
- **THEN** значение отображается как «20»

### Requirement: Удаление записи длинным нажатием

Длинное нажатие на строку записи SHALL открывать контекстное меню в точке
нажатия с двумя пунктами: «Изменить» и «Удалить». Пункт «Изменить» SHALL
располагаться выше пункта «Удалить». Каждый пункт SHALL иметь ведущую
иконку: карандаш у «Изменить», корзина у «Удалить»; иконки SHALL NOT иметь
собственного текстового описания (пункт читается по тексту). Выбор пункта
«Удалить» SHALL открывать алерт подтверждения с кнопками подтверждения и
отмены. Подтверждение SHALL удалять запись через слой данных — запись
исчезает из списка; отмена SHALL закрывать алерт без удаления. Закрытие
без выбора (тап вне меню и алерта) SHALL закрывать их без действий.

#### Scenario: Длинное нажатие открывает меню с пунктом «Удалить»

- **WHEN** пользователь выполняет длинное нажатие на строку записи
- **THEN** открывается контекстное меню
- **AND** меню содержит пункт «Изменить» с иконкой карандаша
- **AND** меню содержит пункт «Удалить» с иконкой корзины
- **AND** пункт «Изменить» расположен выше пункта «Удалить»

#### Scenario: Контекстное меню позиционируется в точке нажатия

- **WHEN** пользователь выполняет длинное нажатие на строку записи
  в координатах (x, y) относительно строки
- **THEN** DropdownMenu позиционируется так, что его top-left
  совпадает с точкой касания

#### Scenario: Строка записи визуально выделяется при показе меню

- **WHEN** пользователь выполняет длинное нажатие на строку записи
- **THEN** строка записи визуально выделяется (фон отличается от
  обычных строк)
- **AND** выделение пропадает, когда контекстное меню закрывается
  (тап вне меню, выбор пункта, системная отмена)

#### Scenario: Подтверждение удаления удаляет запись

- **WHEN** пользователь выбрал «Удалить» и подтвердил удаление в алерте
- **THEN** запись удаляется из хранилища
- **AND** запись исчезает из списка

#### Scenario: Отмена удаления сохраняет запись

- **WHEN** пользователь выбрал «Удалить» и нажал «Отмена» в алерте
- **THEN** алерт закрывается
- **AND** запись остаётся в списке

### Requirement: Пустое состояние списка записей

Когда записей нет, главный экран SHALL показывать заглушку с текстом
вида «Добавьте первую запись» вместо списка.

#### Scenario: Пустой список показывает заглушку

- **WHEN** в хранилище нет записей
- **THEN** вместо списка отображается заглушка с текстом «Добавьте первую
  запись»

### Requirement: FAB главного экрана открывает экран создания записи

Тап по FAB на `MainScreen` SHALL открывать экран создания записи о
выполнении. Остальное поведение `MainScreen` (заголовок, отступы,
остальные требования) не меняется.

#### Scenario: Тап по FAB открывает экран создания записи

- **WHEN** пользователь находится на вкладке «Тренировки» и нажимает FAB
- **THEN** открывается экран создания записи о выполнении

### Requirement: MainScreen Scaffold uses horizontal-only safeDrawing insets

`MainScreen`'s `Scaffold` SHALL set `contentWindowInsets = WindowInsets.safeDrawing.only(WindowInsetsSides.Horizontal)`. The vertical insets are already consumed by `NavigationBar` in the outer `RootScreen`; re-applying them here would shift the FAB upward.

#### Scenario: Insets do not double-subtract

- **WHEN** `MainScreen` is rendered inside `RootScreen`
- **THEN** the FAB sits at the same vertical offset as in the `JetpackDays` reference
- **AND** content body sits flush with the `NavigationBar` top edge via `paddingValues`

### Requirement: Workouts tab labels are localized ru/en

The strings used by the workouts tab — `workouts_title` (for both `NavigationBarItem.label` and `TopAppBar.title`) and `add_workout` (for the FAB `contentDescription`) — SHALL exist in both `res/values/strings.xml` (Russian: "Тренировки" / "Добавить тренировку") and `res/values-en/strings.xml` (English: "Workouts" / "Add workout").

#### Scenario: Russian locale

- **WHEN** the device locale is `ru`
- **THEN** the workouts tab label is "Тренировки"
- **AND** the FAB `contentDescription` is "Добавить тренировку"

#### Scenario: English locale

- **WHEN** the device locale is `en`
- **THEN** the workouts tab label is "Workouts"
- **AND** the FAB `contentDescription` is "Add workout"

### Requirement: Дополнительный вес в строке записи

Строка записи на главном экране SHALL отображать дополнительный вес
второй строкой под строкой «название — значение», когда у записи есть
доп. вес: слева — локализованная метка «Дополнительный вес», справа с
выравниванием по правому краю — значение веса с единицей измерения.
Когда доп. веса нет, строка веса SHALL NOT отображаться — вид строки
записи идентичен текущему (одна строка «название — значение»).

Значение веса SHALL форматироваться так: целые килограммы — без
дробной части («5 кг», не «5.0 кг»), дробные — с дробной частью как
введена («2.5 кг»). Десятичный разделитель — точка, как на экране
ввода веса.

#### Scenario: Целый вес отображается без дробной части

- **WHEN** список отображает запись с доп. весом 5 кг
- **THEN** под строкой значения отображается «Дополнительный вес» слева
  и «5 кг» справа

#### Scenario: Дробный вес отображается с дробной частью

- **WHEN** список отображает запись с доп. весом 2.5 кг
- **THEN** строка веса показывает «2.5 кг»

#### Scenario: Нулевой или отсутствующий вес скрывает строку веса

- **WHEN** список отображает запись без доп. веса (`weight_kg` — `null`
  или 0)
- **THEN** строка веса не отображается
- **AND** строка записи выглядит так же, как до этого изменения

#### Scenario: Метка и единица локализованы ru/en

- **WHEN** язык устройства — русский
- **THEN** метка строки веса — «Дополнительный вес», значение — «5 кг»
- **WHEN** язык устройства — английский
- **THEN** метка строки веса — «Extra weight», значение — «5 kg»

### Requirement: Изменение записи из контекстного меню

Пункт «Изменить» контекстного меню записи SHALL закрывать меню и открывать
экран записи в режиме редактирования для выбранной записи: заголовок
«Изменить запись», форма предзаполнена данными записи (поведение экрана —
в спеке `workout-entry-screen`). Алерт подтверждения удаления SHALL NOT
открываться.

#### Scenario: Выбор «Изменить» открывает экран редактирования

- **WHEN** пользователь выполнил длинное нажатие на строку записи и выбрал
  пункт «Изменить»
- **THEN** контекстное меню закрывается
- **AND** открывается экран записи с заголовком «Изменить запись»
- **AND** форма предзаполнена данными этой записи
- **AND** алерт подтверждения удаления не отображается
