# workouts-main-screen Дельта

## MODIFIED Requirements

### Requirement: MainScreen Scaffold with TopAppBar

`MainScreen` SHALL be a `@Composable fun MainScreen(viewModel: MainViewModel, onAddEntryClick: () -> Unit, modifier: Modifier = Modifier)` annotated with `@OptIn(ExperimentalMaterial3Api::class)`. Its `Scaffold` SHALL contain `topBar = { TopAppBar(title = { Text(stringResource(R.string.workouts_title)) }) }`. The `Scaffold` body SHALL display the list of workout entries or, when there are no entries, the empty-state placeholder (см. «Пустое состояние списка записей»).

#### Scenario: MainScreen renders with localized title

- **WHEN** `MainScreen` is composed with the Russian locale active
- **THEN** the `TopAppBar` displays "Тренировки"
- **AND** the `Scaffold` body displays the list of entries or the empty-state placeholder

## ADDED Requirements

### Requirement: Список записей на главном экране

Тело главного экрана SHALL отображать записи о выполнении в виде
прокручиваемого списка. Записи SHALL быть упорядочены по дате/времени
записи убыванием: новые сверху, старые ниже. Каждая строка SHALL быть
переиспользуемым компонентом: слева — название упражнения, справа с
выравниванием по правому краю — значение подходов и повторов/длительности.
Разделитель между названием и значением (запятая и т.п.) SHALL NOT
отображаться.

#### Scenario: Записи отображаются после сохранения

- **WHEN** пользователь сохранил запись на экране создания и вернулся
  на главный экран
- **THEN** новая запись отображается в списке первой

#### Scenario: Новые записи выше старых

- **WHEN** в списке есть записи с разными датами
- **THEN** запись с более поздней датой/временем расположена выше записи
  с более ранней

#### Scenario: Строка записи: название слева, значение справа

- **WHEN** список отображает запись
- **THEN** название упражнения выровнено по левой части строки
- **AND** значение (подходы, повторы/длительность) выровнено по правой
  части строки без разделителя-запятой между ними

### Requirement: Формат значения записи

Значение в строке записи SHALL формироваться по количеству подходов:
при нескольких подходах — «подходы × значение» (например «4 х 10»), при
одном подходе — только значение (например «10»). Для упражнений на время
формат тот же, значение — длительность записи (примеры — в сценариях
ниже).

#### Scenario: Несколько подходов с повторами

- **WHEN** запись содержит 4 подхода по 10 повторов
- **THEN** значение отображается как «4 х 10»

#### Scenario: Один подход с повторами

- **WHEN** запись содержит 1 подход по 10 повторов
- **THEN** значение отображается как «10»

#### Scenario: Несколько подходов с длительностью

- **WHEN** запись содержит 3 подхода по 20 секунд
- **THEN** значение отображается как «3 х 20»

#### Scenario: Один подход с длительностью

- **WHEN** запись содержит 1 подход длительностью 20 секунд
- **THEN** значение отображается как «20»

### Requirement: Удаление записи длинным нажатием

Длинное нажатие на строку записи SHALL открывать контекстное меню в точке
нажатия с единственным пунктом «Удалить». Выбор пункта SHALL открывать
алерт подтверждения с кнопками подтверждения и отмены. Подтверждение
SHALL удалять запись через слой данных — запись исчезает из списка;
отмена SHALL закрывать алерт без удаления. Закрытие без выбора (тап
вне меню и алерта) SHALL закрывать их без действий.

#### Scenario: Длинное нажатие открывает меню с пунктом «Удалить»

- **WHEN** пользователь выполняет длинное нажатие на строку записи
- **THEN** открывается контекстное меню
- **AND** меню содержит единственный пункт «Удалить»

#### Scenario: Контекстное меню позиционируется в точке нажатия

- **WHEN** пользователь выполняет длинное нажатие на строку записи
  в координатах (x, y) относительно строки
- **THEN** DropdownMenu позиционируется так, что его top-left
  совпадает с точкой касания

#### Scenario: Подтверждение удаления удаляет запись

- **WHEN** пользователь выбрал «Удалить» и подтвердил удаление в алерте
- **THEN** запись удаляется из хранилища
- **AND** запись исчезает из списка

#### Scenario: Отмена удаления сохраняет запись

- **WHEN** пользователь выбрал «Удалить» и нажал «Отмена» в алерте
- **THEN** алерт закрывается
- **AND** запись остаётся в списке

### Requirement: Пустое состояние списка записей

Когда записей нет, главный экран SHALL показывать заглушку с текстом
вида «Добавьте первую запись» вместо списка.

#### Scenario: Пустой список показывает заглушку

- **WHEN** в хранилище нет записей
- **THEN** вместо списка отображается заглушка с текстом «Добавьте первую
  запись»
