# Proposal: workout-entries-list

## Why

Экран создания записи сохраняет записи в БД, но главный экран их не
показывает: пользователь не видит историю тренировок и не может удалить
ошибочную запись. FAB уже открывает создание записи — список записей
завершает базовый цикл «создал → увидел → удалил».

## What Changes

- Реактивный список записей на главном экране (вкладка «Тренировки»):
  новые записи сверху, старые ниже (сортировка по дате/времени записи).
- Переиспользуемый composable-компонент строки записи: слева — название
  упражнения, справа с выравниванием по правому краю — значение
  (подходы и повторы/длительность).
- Формат значения: при нескольких подходах — «4 х 10», при одном —
  просто «10»; длительность отображается так же (пример: «3 х 20», «20»).
- Долгое нажатие на строку открывает контекстное меню в точке нажатия
  с единственным пунктом «Удалить»; удаление подтверждается алертом
  (подтвердить/отмена).
- Пустое состояние: если записей нет — заглушка с текстом вида
  «Добавьте первую запись».
- Слой данных: реактивное чтение всех записей (`Flow`) с названием
  упражнения и сортировкой по дате убыванием.
- Слой данных: валидация обязательного значения по типу упражнения
  (`REPS` → повторы, `TIME` → длительность) — запись без него не
  сохраняется. **BREAKING** для прежнего правила «слой данных не
  навязывает соответствие `measuredBy`» — требование переписывается.

Поиск, фильтрация и редактирование записи — вне рамок этого изменения.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `workouts-main-screen` — тело главного экрана перестаёт быть пустым:
  список записей, формат строки, удаление длинным нажатием, пустое
  состояние.
- `workout-data` — новое требование: реактивный список записей с
  названием упражнения и сортировкой по дате убыванием; переписаны
  требования «Валидация полей записи» и «Поддержка упражнений на
  время» (обязательность значения по `measuredBy`).

## Impact

- `ExerciseEntryDao` — новый запрос-наблюдение с JOIN на `exercises`
  (название упражнения в строке записи) и `ORDER BY date DESC`.
- `EntryValidator` — сигнатура `validate(entry, measuredBy)` + новые
  коды ошибок; `RoomWorkoutDataRepository.addEntry`/`updateEntry`
  грузят упражнение по `exerciseId` перед валидацией.
- `WorkoutDataRepository` / `RoomWorkoutDataRepository` — новый метод
  `entries(): Flow<List<…>>`.
- `ui/screens/main/` — `MainScreen` получает тело: `LazyColumn`,
  компонент строки, контекстное меню, алерт удаления, заглушка пустого
  состояния; новый `MainViewModel` + форматтер значения.
- Строковые ресурсы ru/en: меню удаления, алерт, пустое состояние,
  шаблон значения «4 х 10».
- Тесты: DAO (androidTest), репозиторий (androidTest), форматтер и
  ViewModel (JVM), экран (androidTest Compose).
- Новых зависимостей нет; миграция БД не нужна (схема не меняется).
