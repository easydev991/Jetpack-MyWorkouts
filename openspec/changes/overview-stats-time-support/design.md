# Design: TIME-упражнения в статистике обзора

## Context

`ComputeCategoryStats` (Decision 4 архивного `overview-screen`) строит
`categoryTotals`/`exerciseTotals` только из REPS-записей (`repsVolume()`
возвращает 0 для TIME) — TIME-категория не видна в донате и легенде,
drill-down для неё недостижим (нет строки легенды, по которой кликают).
`StatsUiState.isEmpty` считается в VM как `categoryTotals.isEmpty()` —
только-TIME пользователь видит «Нет тренировок за выбранный период».
Вкладки «Рекорды» (`setValue() = reps ?: durationSec ?: 0`) и
«Активность» (счёт по записям) TIME уже учитывают — не трогаются.

## Goals / Non-Goals

**Goals:**

- TIME-категории и упражнения в донате, легенде и drill-down наравне с REPS.
- Универсальная единица долей — подходы (sets); значения легенды — в
  естественных единицах (повторения и/или адаптивная длительность).
- Честное пустое состояние: «нет записей за период вообще».

**Non-Goals:**

- Переключаемый «режим длительности» — TIME поддерживается постоянно,
  без настроек.
- Изменения вкладок «Рекорды» и «Активность», списка записей drill-down
  (формат «подходы × длительность» уже реализован в `drillEntryValueText`).
- Смешивание секунд и повторений в одной сумме — по-прежнему запрещено.

## Decisions

### Decision 1: Доли доната — по подходам (sets)

Доля категории в донате = сумма `sets` её записей за период; доля
упражнения в drill-down = сумма `sets` упражнения. Обоснование:

- Подход — единственная величина, осмысленная для обоих типов измерения
  (у TIME-записи `durationSec` — длительность одного подхода, у REPS —
  `reps` за подход); секунды и повторения в одной сумме смешивать
  бессмысленно.
- Донат показывает структуру нагрузки по категориям, а не абсолюты —
  относительные доли по подходам корректны.
- Это заменяет прежнее правило «донат по повторам» (Decision 4 архива);
  «N повт.» в значении легенды остаётся только для REPS-категорий.
- Сортировка категорий и упражнений — по сумме подходов убывание, затем
  по имени (сохранение прежнего правила сортировки, где объём теперь
  подходы).

### Decision 2: Значение легенды — состав по типам записей

`CategoryTotal`/`ExerciseTotal` расширяются: `totalSets` (единица долей
и сортировки), `totalReps` (сумма «подходы × повторы» REPS-записей),
`totalDurationSec` (сумма `sets × durationSec` TIME-записей). Все данные
уже есть в `EntryWithExercise`. Выбор отображения по составу записей:

- `totalReps > 0 && totalDurationSec == 0` → «N повт.» (как сейчас);
- `totalDurationSec > 0` → длительность компактным форматом (Decision 3);
- оба ненулевые (смешанная категория) → «N повт. · M <ед.>», разделитель
  — существующий шаблон `entry_value_separator` (« х ») не подходит,
  нужен отдельный строковый ресурс с « · ».

Выбор единицы значения — на слое UI (композиция из строковых ресурсов),
домен отдаёт только суммы. `isEmpty` в VM — по наличию записей периода
(`drillGroups` непуст, т.е. есть записи любого типа), а не по
`categoryTotals`.

### Decision 3: Компактный одноединицный формат длительности

Существующий `formatDurationResource` («1 ч 20 мин», многосоставный)
для легенды не подходит — нужен компактный формат с одной единицей.
Решение: новая маленькая функция рядом в `ui/util/DurationFormatter.kt`
(`formatStatsDurationCompact`), а не реюз многосоставного. Правила:

- < 60 сек → «N сек.»; < 3600 сек → «N мин.»; < 86400 сек → «N ч.»;
  иначе «N дн.»; пороги строгие (ровно 3600 → «1 ч.», ровно 86400 →
  «1 дн.»); дробное — округление до ближайшего целого (90 сек → «2 мин.»).
- Все четыре единицы — новые формат-строки с точкой (ru: «сек.»/«мин.»/
  «ч.»/«дн.», en: «sec.»/«min.»/«h.»/«d.»): существующие
  `entry_duration_minutes_short` = «мин» и `entry_duration_seconds_short`
  = «сек» (strings.xml:93–94, values-en:93–94) — без точки и для легенды
  не подходят; часы/дни без склонений.
- Чистая функция с параметрами-строками (тестируемая) + `@Composable`
  обёртка над ресурсами — паттерн `formatDuration`.

### Decision 4: UI — значения легенды строкой

`StatsLegendRow.value: Int` заменяется готовым текстом значения
(`valueText: String`), резолвимым в `legendItems` через новые
`@Composable`-хелперы; `donutSlices` переключается с `totalReps` на
`totalSets`. Демо-данные превью дополняются TIME-категорией (CARDIO:
бег/скакалка — `previewEntry` уже умеет TIME) и смешанной категорией,
превью светлой+тёмной темы по конвенциям; новое превью только-TIME
состояния не требуется — TIME-категория видна в существующих превью.

## Risks / Trade-offs

- [Доля по подходам меняет привычные пропорции доната у REPS-пользователей
  (было «сумма повторов»)] → осознанная замена правила владельцем;
  единство обоих типов измерения важнее.
- [`isEmpty` по `drillGroups` — записи вне периода по-прежнему пустой
  период] → ожидаемое поведение, тест VM фиксирует.
- [detekt: новые ветки в `legendItems`/форматтере] → компактные чистые
  функции, `MagicNumber` через именованные константы порогов; лимит
  `maxIssues: 5` не поднимается.
