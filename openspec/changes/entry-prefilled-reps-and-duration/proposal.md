# Proposal

## Why

При создании записи пользователю каждый раз приходится вручную вводить
те же повторы, длительность и доп. вес, что и в прошлый раз, хотя
почти всегда значения совпадают с последней тренировкой. Предзаполнение
пустых полей из истории упражнения убирает рутинный ввод и снижает
количество опечаток.

## What Changes

- Режим создания записи (EntryCreateScreen): при выборе упражнения пустые
  поля предзаполняются из истории этого упражнения:
  - «Повторы» — reps последней записи упражнения (если поле пустое);
  - «Длительность» — durationSec той же последней записи (если не выбрано);
  - «Доп. вес» — вес из последней записи с весом, но только если записи
    с весом составляют строго больше половины всех прошлых записей
    упражнения (если поле веса не изменено пользователем);
  - «Подходы» никогда не предзаполняются (остаются 1).
- Непустые поля не перезаписываются; предзаполнение действует только
  в режиме создания — редактирование существующей записи не меняется
  вообще.
- Добавлен запрос истории упражнения: упорядоченный снимок записей
  (ORDER BY date DESC, created_at DESC) через ExerciseEntryDao →
  WorkoutDataRepository; из него выводятся и «последняя запись»,
  и статистика веса.
- Защита от гонок: результат применяется, только если упражнение не
  сменилось, поля не изменены пользователем и режим — создание.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `workout-entry-screen`: в режиме создания при выборе упражнения пустые
  типозависимое поле (повторы/длительность) и поле доп. веса
  предзаполняются из истории упражнения по строгим правилам; прежний
  текст требования «поле появляется с дефолтом» уточняется условием
  предзаполнения. Режим редактирования и правило «подходы = 1»
  не меняются.

## Impact

- `app/src/main/java/com/myworkouts/data/db/ExerciseEntryDao.kt` — новый
  запрос истории упражнения.
- `app/src/main/java/com/myworkouts/data/repository/WorkoutDataRepository.kt`,
  `RoomWorkoutDataRepository.kt` — прокидывание запроса, Result + try/catch.
- `app/src/main/java/com/myworkouts/ui/viewmodel/EntryCreateViewModel.kt`
  (`onExerciseChange`) — асинхронное предзаполнение в viewModelScope.
- `app/src/main/java/com/myworkouts/ui/state/EntryCreateUiState.kt` —
  добавить поле `weightTouched: Boolean = false` (флаг «поле веса
  изменено пользователем»; design D5).
- Тесты: ViewModel (`app/src/test/`); DAO и репозиторий, UI-тесты экрана
  (`app/src/androidTest/`).
- Схема БД не меняется (только новый SELECT).
