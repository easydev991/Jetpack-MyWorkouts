# Design

## Context

Фикс затрагивает четыре экрана/компонента, но все изменения — точечные семантические. Ключевая развилка — как дать скринридеру доступ к long-press-меню; остальные три пункта механические.

## Goals / Non-Goals

- Goals: контекстные меню трёх списков доступны из TalkBack; заголовки секций навигируемы; вкладки озвучиваются один раз; лейбл чекбокса переключает его.
- Non-Goals: полный a11y-аудит (ошибки форм — отдельная задача), `AccessibilityChecks.enable()`, изменение визуального UX и жестов.

## Decisions

- **D1. Accessibility-действие через `customActions`, не `combinedClickable`.**
  У строк нет `onClick`; `combinedClickable` требует `onClick` — фиктивный
  клик услышал бы «дважды коснитесь для активации», который ничего не делает.
  `Modifier.semantics { customActions = listOf(CustomAccessibilityAction(label) { … }) }`
  добавляет действие в меню действий TalkBack, не трогая жесты и UX.
  Строки уже имеют `semantics(mergeDescendants = true)` — действие
  добавляется в тот же блок. Выбор: минимальное, честное решение.
- **D2. Офсет меню при открытии из a11y — центр строки.**
  Колбэк long-press принимает офсет в координатах контейнера меню
  (`onLongPress(item, offset)`). Для a11y-действия точка касания
  отсутствует: центр строки вычисляет вызывающая сторона — в главном
  списке `EntryListItems` уже отслеживает позицию строки для
  long-press и достраивает центр из её размера; трекинг в самой
  строке дублировал бы это наблюдение. `Offset.Unspecified` не
  вводим — контракт колбэка не меняем. Для каталога и архива
  (общий хелпер `applyLongPress`) действие отдаёт `positionInRoot`
  без центра — меню открывается от верхнего левого угла строки;
  поведение проверено на эмуляторе и сохранено как есть.
- **D3. Общий хелпер — одна точка для двух экранов.**
  `ExerciseMenuHelpers.applyLongPress` (ExercisesScreen + ArchivedExercisesScreen)
  получает `customActions` внутри хелпера — оба экрана фиксируются одной
  правкой. Главный список — отдельная правка: блок `semantics`
  строки живёт в `EntryListItemRow` (`EntryListItemRow.kt:92–99`),
  колбэк long-press сегодня есть только у `EntryListItems`
  (`MainScreen.kt:327`) — его нужно прокинуть в `EntryListItemRow`
  параметром.
- **D4. Один строковый ресурс на все три списка.**
  `a11y_open_menu` («Открыть меню» / "Open menu") в
  `values/strings.xml` и `values-en/strings.xml`; действие
  одинакового смысла на всех трёх экранах — дублировать ресурс
  не нужно.
- **D5. Заголовки секций — `semantics { heading() }`.**
  В `SectionHeader` к существующему `Text` добавляется
  `Modifier.semantics { heading() }`. Кастомных стилей не нужно —
  TalkBack сам объявляет заголовок и включает навигацию по заголовкам.
- **D6. Вкладки — `contentDescription = null` явно.**
  В `RootScreen` иконке `NavigationBarItem` ставится `contentDescription = null`
  вместо дублирующего `title`: лейбл вкладки и так смержен с элементом,
  озвучивается один раз. Комментарий-обоснование рядом.
- **D7. Чекбокс алерта — единая кликабельная область (`toggleable`,
  по образцу радио-строк).**
  `Row` с лейблом и чекбоксом получает
  `Modifier.toggleable(value, role = Role.Checkbox, onValueChange = …)`,
  самому `Checkbox` ставится `onCheckedChange = null` — тот же паттерн, что
  уже применяется в `AppearanceScreen` для радио (`selectable` +
  `onClick = null`; у M3 `RadioButton` отключается именно `onClick`).
  Лейбл и чекбокс становятся единой кликабельной областью; отдельный
  `Modifier.clickable` на `Text` не нужен.

  Постархивная правка вёрстки (M3 1.4.0, проверено на эмуляторе):
  в null-ветке `Checkbox` не применяет слот
  `minimumInteractiveComponentSize` — бокс рендерится вплотную к
  лейблу и не центрирован, поэтому чекбоксу явно задаётся
  `Modifier.size(48.dp)` (восстанавливает геометрию интерактивного
  чекбокса). `padding(top = 8.dp)` ставится ДО `toggleable` — иначе
  подсветка long-press включает пустой отступ сверху и контент
  выглядит не отцентрированным в зоне нажатия.

## Risks / Trade-offs

- [`customActions` не заменяет real onClick] → для switch-access без TalkBack
  действия доступны через скан; полноценный второй путь к меню (кнопка «…»)
  сознательно отложен — это UX-изменение вне скоупа.
- [`onGloballyPositioned` на каждой строке] → один лямбда-колбэк на композицию,
  без пересчётов; списки малы (десятки строк), оверхеда нет.
- [Тесты long-press остаются на жестах] → новые тесты добавляют проверку
  a11y-канала (наличие действия по локализованному лейблу + его выполнение),
  старые не трогаем.

## Migration Plan

Без миграций и данных. Изменения UI-семантики, обратная совместимость полная.
