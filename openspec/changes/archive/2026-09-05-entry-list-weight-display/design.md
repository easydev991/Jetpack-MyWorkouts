## Context

`exercise_entries.weight_kg` (Double?) уже хранится и вводится на экране
создания записи; экран создания нормализует пустой/нулевой ввод в `null`
(`takeIf { it > 0.0 }`), а `EntryValidator` допускает `weightKg >= 0`
(0 валиден и отличим от `null`). Сегодня `0.0` попадает в БД только
прямыми DAO-записями (тесты `ExerciseEntryUpdateTest`): единственный
production-путь записи — `addEntry`. `updateEntry` прогоняет валидатор,
но production-вызовов не имеет — экран редактирования только запланирован
(`entry_edit/{id}` в `Screen.kt`), и с его появлением `0.0` станет
достижим из UI. Главный экран читает записи через JOIN-проекцию
`observeEntries` → `EntryListItemEntity` → `toListItem()` →
`EntryListItem`; в проекции веса нет. См. proposal.md — Why.

## Goals / Non-Goals

**Goals:**

- Протащить `weightKg` от SQL-проекции до `EntryListItemRow` без смены
  схемы БД и без правок репозитория/ViewModel (они только проксируют Flow).
- Показывать вес второй строкой в строке записи; без веса — UI байт-в-байт
  как сейчас.

**Non-Goals:**

- Экран создания/редактирования записи не меняется (вес уже вводится).
- Сортировка/агрегаты по весу, вес в контекстном меню/алерте удаления.
- Spec `workout-data` не меняется: проекция списка — деталь реализации
  главного экрана, поведение репозитория не меняется.

## Decisions

### Decision 1: Расширение проекции, без миграции

`EntryListItemEntity` — не `@Entity`, Room строит его из SQL. Добавляем
`weightKg: Double?` в data class и `e.weight_kg AS weightKg` в SELECT
`observeEntries`. Схема БД и версия `WorkoutDatabase` не меняются.
Альтернатива — подписка на полные `ExerciseEntry` и JOIN в памяти:
тягала бы лишние `comment`/`createdAt` и дублировала JOIN.

### Decision 2: Строка веса показывается при `weightKg > 0.0`

Валидатор пропускает `0.0` (0 отличим от `null`), но экран создания
сохраняет 0 как «нет веса». Для отображения 0 кг доп. веса — то же, что
«нет веса»: строка скрывается. Условие `weightKg != null && weightKg > 0.0`
эквивалентно просто `weightKg > 0.0` (null-safe в Kotlin). Альтернатива
`!= null` показывала бы бессмысленную строку «0 кг».

### Decision 3: Формат — чистая JVM-функция рядом с `formatEntryValue`

`formatWeightKg(weightKg: Double): String` в `EntryValueFormatter.kt`:
`toString().removeSuffix(".0")` — у целых `Double.toString()` даёт
«5.0», суффикс срезается («5», не «5.0»); дробные не затрагиваются
(«2.5» — Kotlin даёт кратчайшее представление, «2.50» после парса
ввода невозможно, значит суффикс «.0» встречается только у целых). Единица и метка — в ресурсах: `entry_list_weight_label`
(«Дополнительный вес»/«Extra weight») и `entry_list_weight_value`
(«%1$s кг»/«%1$s kg»). Разделитель — точка, как на экране ввода
(санитайзер приводит запятую к точке); `NumberFormat` по локали
отклонён — показывал бы «2,5» при вводе «2.5».

### Decision 4: `Column` из двух `Row` в `EntryListItemRow`

Фон-анимация, padding и `semantics(mergeDescendants)` переносятся на
внешний `Column` (семантика `Selected` для androidTest остаётся на
объединённом узле строки). Первый `Row` — текущий контент, но оба
текста (название и значение) получают `fontWeight = FontWeight.Medium`
(w500) — основная строка чуть выраженнее суб-строки веса (вариант
выбран по живому демо трёх начертаний на эмуляторе). Второй `Row` —
`SpaceBetween`: метка и значение, стиль `bodyMedium` обычного
начертания, метка цветом `onSurfaceVariant` (суб-строка слабее
основной). Второй `Row` рендерится только при `weightKg > 0.0`.
Между строками — `Arrangement.spacedBy(4.dp)`; при одной строке
отступ не действует.
`modifier` (long-press, позиция) остаётся на внешнем контейнере —
жесты не меняются.

### Decision 5: `weightKg: Double? = null` — дефолт только в `EntryListItem`

`EntryListItem` конструируется в маппере `toListItem()`, фикстурах тестов
и превью — дефолт `= null` оставляет их компилируемыми без правок; новым
тестам вес передаётся явно. В `EntryListItemEntity` дефолт не нужен:
Room (2.8.4) заполняет поле из SELECT (`e.weight_kg AS weightKg`),
ручных конструкций проекции в коде нет.

## Risks / Trade-offs

- [Двойные веса вида 12.25 показываются как есть («12.25 кг»)] → так
  введено пользователем; округление до 0.5 кг — отдельная задача, если
  понадобится.
- [`MainScreenTest` фикстуры без веса продолжают проходить, но не
  проверяют новую строку] → добавляем отдельные сценарии показа/скрытия
  строки веса (tasks 4.1–4.2).
- [Хвостовые нули/артефакты Double] → после парса одного значения из
  строки ввода `toString()` даёт кратчайшую форму; отдельная обработка
  не нужна.

## Migration Plan

Изменение чисто читающее; схема БД не меняется, откат — revert коммита.
