# Spec Delta: category-data

## MODIFIED Requirements

### Requirement: Архивация и восстановление категории

Репозиторий SHALL предоставлять `setCategoryArchived(id: Long, isArchived:
Boolean): Result<Unit>` — единый метод архивации и восстановления, по образцу
`setArchived` упражнений. Метод SHALL быть доступен и для стандартных, и для
кастомных категорий. Несуществующий id SHALL возвращать `Result.failure`
(«Категория не найдена» — race между сбором списка и подтверждением).
Архивация категории SHALL NOT менять упражнения, ссылающиеся на неё: они
остаются со своей категорией и отображают её как есть. Реактивные подписки
на списки категорий SHALL обновляться без ручного refresh.

Архивация (`isArchived = true`) SHALL отклоняться типизированным
исключением (`LastActiveCategoryException` в `Result.failure`), если
категория — единственная активная в каталоге (остальные в архиве или
удалены): опустошение активного списка категорий делает создание
упражнения невозможным (пикер категорий в форме пуст). Стандартные
категории считаются наравне с кастомными. Восстановление
(`isArchived = false`) SHALL NOT ограничиваться.

#### Scenario: Архивация стандартной категории

- **WHEN** вызывается `setCategoryArchived(id, true)` для стандартной
  категории CARDIO, когда есть и другие активные категории
- **THEN** операция завершается успехом
- **AND** категория исчезает из активного списка и появляется в архивном
- **AND** упражнения категории CARDIO остаются без изменений

#### Scenario: Восстановление категории

- **WHEN** вызывается `setCategoryArchived(id, false)` для архивной категории
- **THEN** операция завершается успехом
- **AND** категория возвращается в активный список

#### Scenario: Несуществующий id отклоняется

- **WHEN** вызывается `setCategoryArchived(999, true)` для несуществующего id
- **THEN** операция завершается `Result.failure`
- **AND** данные не меняются

#### Scenario: Архивация последней активной категории отклоняется

- **WHEN** категория с id = 3 — единственная активная (остальные
  заархивированы или удалены) AND вызывается `setCategoryArchived(3, true)`
- **THEN** операция завершается
  `Result.failure(LastActiveCategoryException)`
- **AND** категория остаётся в активном списке

#### Scenario: Восстановление последней активной категории разрешено

- **WHEN** активна ровно одна категория AND вызывается
  `setCategoryArchived(id, false)` для архивной категории
- **THEN** операция завершается успехом — восстановление не ограничивается
- **AND** активных категорий становится две

### Requirement: Удаление категории

Удаление категории SHALL быть возможным только при выполнении обоих условий:
категория кастомная (`isCustom = true`) И на неё не ссылается ни одно
упражнение — активное ИЛИ архивное. Удаление SHALL возвращать `Result<Unit>`;
ошибки репозиторий SHALL доставлять типизированными исключениями
(`StandardCategoryDeletionException`, `CategoryInUseDeletionException` — по
образцу исключений удаления упражнения) внутри `Result.failure`. Sealed
`DeleteCategoryError` с вариантами `UsedByExercises`, `StandardCategory`,
`Other` (по образцу `DeleteExerciseError`) — контракт маппинга исключений
в `ExercisesViewModel`, а не содержимое `Result`. Стандартная категория SHALL быть неудаляемой
(`StandardCategory`). Категория с exercises-ссылками SHALL быть неудаляемой
(`UsedByExercises`). Удаление SHALL принимать идентификатор категории:
`deleteCategory(id: Long): Result<Unit>` — по образцу `deleteExercise(id)`
(существующий репозиторий везде использует `id` для удалений и
архивации); `id` берётся из строки списка (`Category` содержит и
`id`, и `name` — `LazyColumn key = { it.id }`). Уровнем ниже упражнения
ссылаются на категорию по имени (без FK — design-документ исходного
изменения категорий `2026-10-06-custom-categories`, Decision 1) — это
влияет на пре-чек `categoryNamesWithLinkedExercises(): Flow<Set<String>>`,
но не на сигнатуру самой операции удаления: в транзакции строка
категории всё равно читается для проверки `isCustom` →
`StandardCategoryDeletionException`. Удаление несуществующей категории
(по `id`) SHALL завершаться ошибкой.

Дополнительное условие: категория SHALL NOT быть удаляемой, если она —
единственная активная в каталоге (отклонение
`LastActiveCategoryException`). Pre-check «последний активный» SHALL
выполняться внутри существующей транзакции после проверок `isCustom`
и отсутствия ссылок упражнений.

#### Scenario: Удаление неиспользуемой кастомной категории

- **WHEN** удаляется кастомная категория без упражнений, когда есть
  и другие активные категории
- **THEN** операция завершается успехом
- **AND** категория отсутствует в списке категорий

#### Scenario: Используемая категория неудаляема

- **WHEN** удаляется категория, на которую ссылается хотя бы одно упражнение
  (в том числе архивное)
- **THEN** операция завершается ошибкой `UsedByExercises`
- **AND** категория и упражнения остаются без изменений

#### Scenario: Стандартная категория неудаляема

- **WHEN** удаляется стандартная категория (`isCustom = false`)
- **THEN** операция завершается ошибкой `StandardCategory`

#### Scenario: Удаление последней активной категории отклоняется

- **WHEN** кастомная категория без ссылок упражнений — единственная
  активная AND вызывается `deleteCategory(id)`
- **THEN** операция завершается
  `Result.failure(LastActiveCategoryException)`
- **AND** категория остаётся в списке категорий

#### Scenario: Удаление архивной категории при последней активной разрешено

- **WHEN** активна ровно одна категория AND вызывается удаление
  архивной кастомной категории без ссылок упражнений
- **THEN** операция завершается успехом
- **AND** архивная категория удалена, единственная активная остаётся
