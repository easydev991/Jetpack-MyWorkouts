# Proposal: fix-entry-list-live-update

## Why

На устройстве воспроизводятся два дефекта живого обновления списка записей
на главном экране: после сохранения отредактированной записи отображается
старое название упражнения, а после сохранения новой записи запись не
появляется — в обоих случаях до перезапуска приложения. Это нарушение
сценария «Записи отображаются после сохранения» требования «Список записей
на главном экране» спеки `workouts-main-screen`: список обязан
актуализироваться после сохранения без перезапуска. Механика дефекта —
design.md (Context); дефект интермиттентный (маскируется перезапуском
подписки), поэтому репро-тест — обязательная часть фикса: аналогичный
дефект каталога уже закрывался в `create-exercise` именно так.

## What Changes

- Перенос композиционного корня ручного DI (`WorkoutDatabase`,
  `RoomWorkoutDataRepository`, `AppSettingsDataStore`) из `MainActivity`
  в `MyWorkoutsApplication`: один инстанс БД/репозитория на процесс
  вместо одного на Activity.
- Регистрация `MyWorkoutsApplication` в `AndroidManifest.xml`.
- `MainActivity` получает зависимости из `Application` (создания БД
  в `onCreate` больше нет — пересоздание Activity больше не плодит
  инстансы).
- Три интеграционных androidTest'а на реальном приложении по образцу
  `ExerciseCreateLiveUpdateIntegrationTest` — по одному на каждый сценарий
  спеки: A «Изменённая запись отображается при быстром возврате»,
  C «Новая запись отображается при быстром возврате», B «Список актуален
  после пересоздания Activity». Детерминированный репро — сценарий B.
  Детали и ожидаемая зелёность — design.md Decision 2, 3.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `workouts-main-screen`: добавляется новое требование «Живое обновление
  списка записей без перезапуска приложения» с тремя сценариями: запись
  отображается при быстром возврате на главный экран сразу после
  сохранения (редактирование и создание) и после пересоздания Activity
  (изменение конфигурации). Существующие требования не меняются.

## Impact

- `app/src/main/java/com/myworkouts/MainActivity.kt` — создание БД и
  репозитория убирается, зависимости берутся из Application.
- Новый `app/src/main/java/com/myworkouts/MyWorkoutsApplication.kt` —
  композиционный корень (планировался структурой проекта: `di/`,
  `MyWorkoutsApplication.kt` в AGENTS.md помечены как ещё не созданные).
- `app/src/main/AndroidManifest.xml` — `android:name=".MyWorkoutsApplication"`.
- Новый androidTest-класс живого обновления списка записей (реальное
  приложение, файловая БД, `createAndroidComposeRule<MainActivity>`).
- Существующие androidTest'ы, создающие второй инстанс БД для подготовки
  данных (`ExerciseCreateLiveUpdateIntegrationTest`), не меняются — их
  поведение гарантируется тем же фиксом.
- Слой данных (`RoomWorkoutDataRepository`, DAO, миграции) не меняется.
