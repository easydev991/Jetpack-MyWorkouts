## MODIFIED Requirements

### Requirement: Единый каталог для стандартных и пользовательских упражнений

Пользовательские упражнения SHALL сохраняться в тот же каталог, что и
стандартные, с пометкой «создано пользователем». Для создания упражнения
SHALL требоваться название и категория; комментарий SHALL быть опциональным.
Каждое упражнение каталога — стандартное и пользовательское — SHALL иметь
тип измерения `measuredBy` (`REPS` — упражнение на повторы, `TIME` —
упражнение на время); при создании пользовательского упражнения без явного
указания типа SHALL применяться `REPS`. Тип измерения SHALL сохраняться
вместе с упражнением и SHALL быть доступен при чтении каталога.
Идентификатор упражнения SHALL генерироваться системой. Каждое упражнение
каталога SHALL иметь булевый флаг `isArchived` (`false` — упражнение
активно и видно в каталоге; `true` — упражнение скрыто из каталога и
доступно только через экран архива). По умолчанию `isArchived` SHALL быть
`false` (новые и существующие упражнения — активные). В Room-сущности
`ExerciseEntity` поле SHALL храниться как `INTEGER NOT NULL DEFAULT 0`
через `@ColumnInfo(name = "is_archived", defaultValue = "0")` —
default-значение исключает миграцию при условии
`fallbackToDestructiveMigration` (приложение ещё не в релизе).

#### Scenario: Создание пользовательского упражнения

- **WHEN** пользовательское упражнение «Отжимания на турнике» категории PULL
  с комментарием «широкий хват» сохраняется
- **THEN** оно появляется в каталоге с пометкой «пользовательское»
  AND `isArchived = false` по умолчанию
- **AND** стандартные упражнения остаются неизменными

#### Scenario: Тип измерения по умолчанию при создании

- **WHEN** пользовательское упражнение сохраняется без явного указания
  типа измерения
- **THEN** упражнение сохраняется с `measuredBy = REPS`
  AND `isArchived = false`

#### Scenario: Создание упражнения «на время»

- **WHEN** пользовательское упражнение (например, «стойка на руках»)
  сохраняется с `measuredBy = TIME`
- **THEN** при чтении каталога упражнение возвращается с `measuredBy = TIME`
  AND `isArchived = false`

### Requirement: Поиск и сортировка каталога

Каталог SHALL предоставляться отсортированным: сортировка активных
упражнений — `is_custom DESC, created_at DESC, name COLLATE NOCASE`
(name — без учёта регистра); сортировка архивных упражнений — та же,
отдельный SQL-запрос. Фильтрация по подстроке названия SHALL
выполняться без учёта регистра; пустая подстрока SHALL возвращать
весь активный каталог (только упражнения с `isArchived = false`).
Архивные упражнения (`isArchived = true`) SHALL NOT попадать в
результат `exercises(query)` — они доступны через отдельный метод
`archivedExercises()`.

#### Scenario: Поиск по подстроке

- **WHEN** запрашивается каталог с подстрокой «под»
- **THEN** возвращаются только активные упражнения с «под» в названии
  (например, «Подтягивания», «Подъёмы ног в висе»); архивные
  упражнения с «под» в названии НЕ попадают в результат
- **AND** результат отсортирован по `is_custom DESC, created_at DESC,
  name COLLATE NOCASE`

#### Scenario: Пустой запрос возвращает весь каталог

- **WHEN** запрашивается каталог с пустой подстрокой
- **THEN** возвращаются все упражнения активного каталога
  (`isArchived = false`); архивные упражнения НЕ попадают в
  результат

### Requirement: Снимки каталога и записей

Репозиторий SHALL предоставлять разовые снимки данных: `getAllExercises`
— ВСЕ упражнения каталога (стандартные, пользовательские, активные и
архивные — без фильтрации по `isArchived`), `getAllEntries` — все
записи о выполнении. `getAllExercises()` используется для экспорта
резервной копии (`app-data-screen`) и дедупликации импорта: архивные
упражнения включаются в снимок, чтобы при импорте в новый экземпляр
БД сохранялся весь набор. Восстановление архивного состояния
пользователя — задача use-case импорта; репозиторий возвращает
данные как есть.

#### Scenario: Снимок возвращает полный каталог

- **WHEN** вызван `getAllExercises` при непустом каталоге
- **THEN** возвращены все упражнения — стандартные и пользовательские

#### Scenario: Снимок включает архивные упражнения

- **WHEN** в каталоге есть и активные, и архивные упражнения
- **THEN** `getAllExercises()` возвращает и активные, и архивные
  в едином списке (с `isArchived` каждого упражнения)

### Requirement: Массовый импорт данных

Репозиторий SHALL предоставлять транзакционную операцию
`importData(exercises, entries)`: вставка только переданных данных,
разрешение имени упражнения в id внутри той же транзакции; при любой
ошибке — откат без частичных вставок. Дедупликация и валидация
выполняются выше репозитория (use-case); репозиторий отвечает только за
транзакционное хранение. Вставляемые из файла упражнения SHALL получать
id от БД (`autoGenerate`); значение `isArchived` импортируемого
упражнения SHALL сохраняться как есть (если импортируется архивное —
оно остаётся архивным в новом экземпляре БД).

#### Scenario: Импорт откатывается при сбое

- **WHEN** во время `importData` вставка завершается ошибкой
- **THEN** в БД нет изменений из этого импорта

#### Scenario: Импорт разрешает имена в id

- **WHEN** импортируемая запись ссылается на упражнение по имени
- **THEN** внутри транзакции запись связывается с id существующего либо
  вставленного упражнения

#### Scenario: Импорт сохраняет isArchived

- **WHEN** импортируется упражнение с `isArchived = true`
- **THEN** в БД упражнение сохраняется с `isArchived = true`
  (импорт архивного упражнения остаётся архивным)

## ADDED Requirements

### Requirement: Архивация и восстановление упражнений каталога

Репозиторий SHALL предоставлять метод
`setArchived(id: Long, isArchived: Boolean): Result<Unit>` — единый
метод для архивации (`isArchived = true`) и восстановления
(`isArchived = false`). Метод SHALL обновлять существующее упражнение
через `ExerciseDao.update(entity.copy(isArchived = isArchived))`
внутри `runCatching`. Отсутствующий id SHALL возвращать
`Result.failure(IllegalStateException("Упражнение не найдено"))` —
race между сбором списка и подтверждением алерта (не идемпотентно, в
отличие от удаления записи). Прочие ошибки БД SHALL возвращаться
через generic `Result.failure`. Метод SHALL быть доступен и для
стандартных, и для кастомных упражнений — архивация не зависит от
`isCustom`. Реактивные подписки на `exercises()` и `archivedExercises()`
SHALL автоматически обновиться без ручного refresh.

#### Scenario: Архивация активного упражнения

- **WHEN** вызывается `setArchived(7, true)` для активного упражнения
  с id = 7
- **THEN** операция завершается успехом
- **AND** упражнение пропадает из `exercises()` (реактивный Flow
  эмитит новый список без него)
- **AND** упражнение появляется в `archivedExercises()`
- **AND** чтение `getExercise(7)` возвращает упражнение с
  `isArchived = true`

#### Scenario: Восстановление архивного упражнения

- **WHEN** вызывается `setArchived(7, false)` для архивного упражнения
  с id = 7
- **THEN** операция завершается успехом
- **AND** упражнение пропадает из `archivedExercises()`
- **AND** упражнение появляется в `exercises()` в позиции согласно
  текущей сортировке
- **AND** `getExercise(7)` возвращает упражнение с `isArchived = false`

#### Scenario: Архивация несуществующего упражнения отклоняется

- **WHEN** вызывается `setArchived(999, true)` для несуществующего id
- **THEN** операция завершается `Result.failure` с сообщением
  «Упражнение не найдено»
- **AND** каталог остаётся без изменений

#### Scenario: Архивация стандартного упражнения

- **WHEN** вызывается `setArchived(3, true)` для стандартного упражнения
  (`isCustom = false`) с id = 3
- **THEN** операция завершается успехом (архивация разрешена и для
  стандартных)
- **AND** упражнение пропадает из `exercises()` и появляется в
  `archivedExercises()`

### Requirement: Реактивный список архивных упражнений

Репозиторий SHALL предоставлять `archivedExercises(): Flow<List<Exercise>>`
— реактивный список всех упражнений с `isArchived = true`. Сортировка —
та же, что у `exercises()`: `is_custom DESC, created_at DESC, name
COLLATE NOCASE` (контракт сортировки зафиксирован в
`exercises-screen/spec.md`, требование «Сортировка каталога —
кастомные сверху, новые первые»). При архивации/восстановлении
упражнения реактивный Flow SHALL эмитить обновлённый список без ручного
refresh.

#### Scenario: Архив пуст

- **WHEN** ни одно упражнение не заархивировано
- **THEN** `archivedExercises()` эмитит пустой список

#### Scenario: Архив содержит одно упражнение

- **WHEN** в БД есть одно заархивированное упражнение «Бег»
- **THEN** `archivedExercises()` эмитит список с этим упражнением

#### Scenario: Реактивность при архивации

- **WHEN** активное упражнение архивируется через `setArchived(id,
  true)`
- **THEN** подписчик `archivedExercises()` получает обновлённый
  список с добавленным упражнением

#### Scenario: Реактивность при восстановлении

- **WHEN** архивное упражнение восстанавливается через
  `setArchived(id, false)`
- **THEN** подписчик `archivedExercises()` получает обновлённый
  список без восстановленного упражнения

### Requirement: Реактивный счётчик архивных упражнений

Репозиторий SHALL предоставлять `archivedCount(): Flow<Int>` —
реактивный счётчик количества упражнений с `isArchived = true`.
Реализация — через `ExerciseDao.observeArchivedCount()` с
`@Query("SELECT COUNT(*) FROM exercises WHERE is_archived = 1")`.
При архивации/восстановлении упражнения Flow SHALL эмитить
обновлённое значение без ручного refresh. Используется UI для
условной видимости кнопки архива в `TopAppBar` экрана
`ExercisesScreen`.

#### Scenario: Архив пуст — счётчик 0

- **WHEN** ни одно упражнение не заархивировано
- **THEN** `archivedCount()` эмитит 0

#### Scenario: Архив не пуст — счётчик увеличивается реактивно

- **WHEN** в БД есть одно заархивированное упражнение AND
  пользователь архивирует ещё одно активное упражнение через
  `setArchived(id, true)`
- **THEN** `archivedCount()` эмитит 2 (обновлённое значение)

#### Scenario: Восстановление уменьшает счётчик

- **WHEN** в архиве 2 упражнения AND пользователь восстанавливает
  одно из них через `setArchived(id, false)`
- **THEN** `archivedCount()` эмитит 1
