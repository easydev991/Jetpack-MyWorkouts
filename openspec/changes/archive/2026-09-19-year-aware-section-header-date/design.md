# Design

## Context

`MainScreen.kt:329` — единственный `DateTimeFormatter.ofPattern(
"dd.MM.yyyy")`, который форматирует `section.date` в `EntryListItems`.
Вся логика выбора заголовка (сегодня / вчера / дата) уже живёт
в одном `if/else`-блоке там же (`if (section.date == yesterday) {
yesterdayLabel } else { section.date.format(formatter) }`) — добавляем
третью ветку по году. `DateSection` / `groupEntriesByDate` уже
выдают `LocalDate`, `EntryListItems` помнит `today`/`yesterday` —
новых полей и зависимостей не появляется. `MainScreenSectionsTest`
имеет копию этого же форматтера — `val dateFormatter` на строке 67,
используется в вызовах на строках 164 и 183 — для формирования
ожидаемых строк; копия должна ехать вместе с реализацией.

## Goals / Non-Goals

**Goals:**

- `SectionHeader` датированной секции (не «Сегодня», не «Вчера»)
  показывает день недели + дату без года для текущего года и
  день недели + `dd.MM.yyyy` для архивных дат — обе локали ru/en
  одним шаблоном, без ветвления по `Locale`.
- Покрытие обоих форматов androidTest-кейсами с фиксированными
  датами — граница «этот год» через `LocalDate.now()` нестабильна:
  в 2027 для `today.minusDays(5)` проверяться будет уже архивный
  формат. Сами существующие тесты при этом зелёные при любом годе
  запуска — ожидаемая строка строится той же функцией выбора
  (см. D4), но контраст с кейсом «без года» размывается.

**Non-Goals:**

- Локализация заголовка «Вчера» (уже существует через
  `entry_section_yesterday`).
- Общий хелпер «форматировать дату секции» в `util/` — один
  call-site, дублирование в тесте допустимо (YAGNI: лишняя
  абстракция ради одного использования).
- Аналитика / события на выбор формата — формат — деталь отрисовки,
  поведение пользователя не меняется.

## Decisions

- **D1. Выбор форматтера в `EntryListItems`**: добавляем
  `remember { DateTimeFormatter.ofPattern("EEE, d MMM") }` и второй
  `remember { DateTimeFormatter.ofPattern("EEE, dd.MM.yyyy") }` —
  без явной локали: `ofPattern` сам берёт локаль по умолчанию.
  В существующей
  `if/else`-цепочке добавляется вложенная ветка по году: `if
  (section.date == yesterday) yesterdayLabel else if
  (section.date.year == today.year) currentYearFormatter else
  archiveFormatter`. Оба форматтера — `remember` (как существующий
  `formatter`), создаются один раз на композицию. Альтернатива —
  вынести логику в `private fun formatSectionDate(date: LocalDate,
  today: LocalDate): String`: лишняя абстракция для одного call-site,
  YAGNI.
- **D2. Локаль — системная по умолчанию**: `EEE` и `MMM` —
  локальные сокращения (ru: `Сб`/`сент.`, en: `Sat`/`Sep`); точка
  после сокращённого месяца в ru — стандартный вывод JDK
  (`DateTimeFormatterBuilder.appendText(MONTH)` ставит точку в ru
  для `MMM`), кастом не нужен. Альтернатива — два форматтера
  с ручной подстановкой `if (locale.language == "ru") …`:
  дублирование без выигрыша.
- **D3. ru/en — один шаблон, без ветвления**: и в спеке, и в
  реализации шаблоны `"EEE, d MMM"` и `"EEE, dd.MM.yyyy"` общие
  для обеих локалей; точечный порядок в en (`Sat, 19 Sep`)
  принимается как есть. Альтернатива — `if (isRu) "EEE, d MMM"
  else "EEE, MMM d"`: ручная работа, единообразие теряется.
- **D4. Тесты на фиксированных датах**: для стабильности тестов
  добавляются два новых androidTest-кейса с заранее известными
  датами (`LocalDate.of(2024, 5, 15)` для архивной секции и
  `LocalDate.of(LocalDate.now().year, 5, 15)` для «этого года» —
  НЕ `LocalDate.now()`, так как такая запись попала бы в секцию
  «Сегодня» без заголовка и тесту нечего было бы ассертить),
  без зависимости от того, совпадает ли `today.minusDays(5)` с
  текущим годом. Известный риск: 15 мая текущего года даёт то же
  совпадение с «сегодня» — принимается как низковероятный (тест
  живёт 24 часа в году), а в этот день §1.2/§1.3 пропускаются через
  JUnit `Assume` (tasks §1.2). Существующие тесты
  (`sections_when_entries_across_dates_then_today_has_no_header_…`,
  `sections_when_scrolled_then_date_header_sticks_above_rows`)
  остаются — их копия форматтера (`dateFormatter` на строке 67)
  обновляется под новый контракт; ожидаемая строка для
  `today.minusDays(5)` строится через ту же функцию выбора
  форматтера, что и в реализации, — это и есть причина, почему
  копия форматтера в тесте «едет» вместе с реализацией.
  Следствие: на границе года существующие тесты не падают —
  ожидаемая строка переключается вместе с реализацией; меняется
  лишь то, какой формат они фактически ассертят (в январе для
  `today.minusDays(5)` — архивный, поскольку дата уходит
  в прошлый год).
- **D5. Превью `MainScreenPreview`**: фикстура `sectionsPreviewEntries()`
  (`MainScreenPreview.kt:130–173`) сейчас содержит только `today`,
  `today.minusDays(1)` и `today.minusDays(5)` — обе последние в
  текущем году, и после правки `EntryListItems` превью никогда
  не покажет формат `EEE, dd.MM.yyyy` (архивный). Это нарушает
  AGENTS.md: «ключевые состояния компонента — отдельными
  `@Preview`-функциями». Решение — добавить в фикстуру одну
  запись на фиксированной прошлогодней дате (например,
  `LocalDate.of(LocalDate.now().year - 1, 3, 10)`), чтобы
  `MainScreenContentSectionsPreview` отрисовывал все три формата:
  «Вчера» / `EEE, d MMM` (текущий год) / `EEE, dd.MM.yyyy`
  (архивный). KDoc фикстуры `sectionsPreviewEntries()`
  (`MainScreenPreview.kt:127`) и соседний KDoc превью
  `MainScreenContentSectionsPreview` (`MainScreenPreview.kt:175–177`,
  стоит перед `@Preview`-аннотациями и описывает ту же фикстуру)
  обновляются под новый набор дат. Проверка — рендер превью
  в IDE после реализации.
- **D6. `DateSection` / `groupEntriesByDate` не трогаем**: `section
  .date` уже `LocalDate`, дополнительной работы не нужно. Граница
  «сегодня / вчера / дата» — исключительно в `EntryListItems`.

## Risks / Trade-offs

- [Копия форматтера в `MainScreenSectionsTest` расходится
  с реализацией] → копия переписывается той же функцией
  выбора (вспомогательная `private fun formatSectionDate` в
  тестовом файле), что и в продакшене; расхождение становится
  заметным на этапе ревью.
- [Существующие тесты завязаны на `LocalDate.now()` —
  `today.minusDays(5)`] → на границе года меняется лишь проверяемый
  формат, тесты остаются зелёными (развёрнуто — D4); граница
  оставлена намеренно — старые тесты валидируют актуальное
  поведение «для текущего момента».
- [`Locale.getDefault()` в форматтере — process-singleton JVM] →
  `Configuration.locale` не переключает JVM-локаль; явное
  переключение и восстановление — tasks §1.3.
