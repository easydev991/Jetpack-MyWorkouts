## Why

При случайном закрытии экрана создания/редактирования записи (стрелка «назад»
или системный жест «назад») несохранённые изменения теряются безвозвратно —
пользователь не может отменить действие и восстановить введённые данные.

## What Changes

- При попытке закрыть экран записи (стрелка TopAppBar ИЛИ системный back)
  при наличии несохранённых изменений показывается AlertDialog подтверждения.
- В режиме создания изменения определяются сравнением полей формы
  с дефолтным состоянием (дата и время не учитываются — предзаполняются
  моментом открытия).
- В режиме редактирования изменения — существующий `canSave`: он уже равен
  «форма валидна и есть отличия» (`formValid && hasChanges`, см.
  `EntryCreateUiState`), дополнительной логики не требуется.
- Confirm («Закрыть») закрывает экран, dismiss («Отмена» / тап мимо)
  оставляет экран открытым.
- Успешное сохранение закрывает экран напрямую, без алерта.
- Новые строковые ресурсы: заголовок, текст и кнопка диалога (ru/en).

  исключение пути «сохранение → закрытие» из перехвата.

## Impact

- `ui/state/EntryCreateUiState.kt` — вычисляемое свойство «есть что терять»
  рядом с `canSave`.
- `ui/screens/entry/EntryCreateScreen.kt` — `BackHandler`, диалоговый
  composable, маршрут стрелки «назад» через подтверждение.
- `res/values/strings.xml`, `res/values-en/strings.xml` — 3 новые строки.
- Тесты: unit на логику условий (JUnit 5), Compose UI на поведение диалога.
- Новых зависимостей нет, офлайн-only и manual DI сохраняются.
