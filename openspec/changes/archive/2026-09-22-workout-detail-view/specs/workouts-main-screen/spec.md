# Spec Delta

## ADDED Requirements

### Requirement: Детали записи по тапу на строку

Обычный тап по строке записи SHALL открывать карточку деталей
этой записи поверх главного экрана: карточка отображается по центру экрана,
скругление углов 28dp, боковые отступы 24dp от краёв экрана, фон за
карточкой затемнён скримом. Список записей SHALL оставаться позади карточки
(не заменяться отдельным экраном).

Пока карточка открыта, строка исходной записи SHALL быть визуально выделена
тем же способом, что и при открытом контекстном меню (фон `surfaceVariant`),
но контекстное меню SHALL NOT отображаться. После закрытия карточки
выделение строки SHALL сниматься.

Закрытие карточки SHALL быть доступно тремя эквивалентными способами:
кнопка-крестик в правом верхнем углу карточки (с локализованным описанием
доступности), тап по скриму вне карточки, системная кнопка Back. Каждый
способ SHALL закрывать карточку и снимать выделение строки без каких-либо
побочных действий над записью.

Длинное нажатие на строку SHALL продолжать открывать контекстное меню по
существующему требованию «Удаление записи длинным нажатием» — добавление
обработки тапа SHALL NOT менять поведение длинного нажатия и
accessibility-действия «Открыть меню».

Строка записи SHALL предоставлять локализованное ru/en
accessibility-действие открытия деталей записи: активация действия из меню
действий скринридера SHALL открывать карточку этой записи (паттерн
существующего действия «Открыть меню»).

Данные карточки SHALL браться из уже загруженного списка записей главного
экрана по идентификатору записи — без дополнительного запроса к хранилищу.
Если открытая запись была удалена из хранилища, пока карточка открыта,
карточка SHALL закрываться автоматически. Если запись была изменена, пока
карточка открыта, карточка SHALL отображать актуальные данные записи.

#### Scenario: Тап по строке открывает карточку деталей

- **WHEN** пользователь выполняет обычный тап по строке записи
- **THEN** поверх списка открывается карточка деталей этой записи
- **AND** карточка расположена по центру экрана со скруглением 28dp,
  боковыми отступами 24dp и затемнённым скримом фоном

#### Scenario: Строка выделена, пока открыты детали

- **WHEN** карточка деталей открыта
- **THEN** строка исходной записи визуально выделена (фон отличается от
  обычных строк)
- **AND** контекстное меню не отображается
- **AND** семантика строки `Selected` доступна для UI-тестов

#### Scenario: Закрытие крестиком снимает выделение

- **WHEN** карточка открыта и пользователь нажимает крестик в правом
  верхнем углу карточки
- **THEN** карточка закрывается
- **AND** выделение строки снимается

#### Scenario: Закрытие тапом по скриму

- **WHEN** карточка открыта и пользователь выполняет тап по затемнённой
  области вне карточки
- **THEN** карточка закрывается и выделение строки снимается

#### Scenario: Закрытие системным Back

- **WHEN** карточка открыта и пользователь нажимает системную кнопку Back
- **THEN** карточка закрывается и выделение строки снимается
- **AND** пользователь остаётся на главном экране

#### Scenario: Длинное нажатие продолжает открывать контекстное меню

- **WHEN** пользователь выполняет длинное нажатие по строке записи
- **THEN** открывается контекстное меню «Изменить»/«Удалить» (поведение
  существующего требования), а не карточка деталей

#### Scenario: Тап по другой строке при открытом меню закрывает только меню

- **WHEN** контекстное меню открыто и пользователь выполняет тап по другой
  строке записи
- **THEN** контекстное меню закрывается
- **AND** карточка деталей не открывается (её открывает повторный тап)

#### Scenario: Открытие деталей при открытом меню закрывает меню

- **WHEN** контекстное меню открыто и пользователь активирует
  accessibility-действие «Показать детали» на другой строке записи
- **THEN** контекстное меню закрывается
- **AND** открывается карточка деталей выбранной записи
- **AND** выделена только строка с открытой карточкой

#### Scenario: Accessibility-действие открывает детали

- **WHEN** пользователь скринридера активирует на строке записи
  accessibility-действие «Показать детали»
- **THEN** открывается карточка деталей этой записи

#### Scenario: Удалённая запись закрывает карточку автоматически

- **WHEN** карточка деталей открыта и запись удалена из хранилища
- **THEN** карточка закрывается автоматически

#### Scenario: Изменённая запись отображается в карточке актуально

- **WHEN** карточка деталей открыта и данные записи изменились в хранилище
- **THEN** карточка отображает актуальные данные записи
- **AND** выделение исходной строки сохраняется

#### Scenario: Поворот при открытых деталях сохраняет карточку

- **WHEN** карточка деталей открыта и происходит смена конфигурации
  (поворот экрана)
- **THEN** карточка остаётся открытой с данными той же записи
- **AND** выделение исходной строки сохраняется

### Requirement: Содержимое карточки деталей записи

Карточка деталей SHALL отображать запись целиком по вертикали сверху вниз:
иконка упражнения, название упражнения, значение записи, дата/время
выполнения, комментарий (при наличии).

Иконка упражнения SHALL отображаться по тем же правилам, что и в строке
списка (требование «Иконка упражнения в строке записи»): известный номер —
иконка 24dp, `null`/неизвестный — иконка не отображается. Название
упражнения SHALL быть набором `titleLarge` по центру.

Значение записи SHALL отображаться крупно (`headlineMedium`, цвет `primary`)
в одну строку по правилам требования «Формат значения записи»: при
нескольких подходах — «подходы × значение», при одном — только значение.
При наличии дополнительного веса > 0 к значению
SHALL добавляться суффикс вида «(+ 5 кг)» из ресурса
`entry_details_weight_suffix` (локализован ru/en); при весе 0/`null` суффикс
SHALL NOT отображаться.

Дата/время выполнения SHALL отображаться всегда — стилем `bodySmall` с
цветом `onSurfaceVariant`. Формат — день месяца, месяц, год, часы и минуты
записи (например «20 сентября 2025, 18:30»).

Комментарий записи SHALL отображаться целиком — без ограничения строк и
многоточия (в отличие от строки списка) — внутри тонального блока
`surfaceVariant` со скруглением. При отсутствии комментария (`null`/blank)
блок комментария SHALL NOT отображаться.

#### Scenario: Значение с подходами и весом

- **WHEN** открыта карточка записи: 4 подхода, 10 повторов, вес 5 кг
- **THEN** значение отображается крупно основным цветом в формате
  «4 х 10 (+ 5 кг)»

#### Scenario: Один подход без веса скрывает дефолты

- **WHEN** открыта карточка записи: 1 подход, 12 повторов, без веса
- **THEN** значение отображается как «12» без количества подходов и
  весового суффикса

#### Scenario: Длительность в карточке

- **WHEN** открыта карточка записи на время: 3 подхода по 20 секунд
- **THEN** значение отображается в формате «3 х 20 сек» без весового
  суффикса

#### Scenario: Дата и время отображаются всегда

- **WHEN** открыта карточка любой записи
- **THEN** под значением отображаются дата и время выполнения записи

#### Scenario: Комментарий отображается целиком

- **WHEN** открыта карточка записи с комментарием длиннее двух строк
- **THEN** комментарий отображается полностью в тональном блоке без
  обрезки и многоточия

#### Scenario: Пустой комментарий не отображается

- **WHEN** открыта карточка записи с комментарием `null` или blank
- **THEN** блок комментария не отображается
