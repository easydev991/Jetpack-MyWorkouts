# Proposal

## Why

Строка списка на главном экране даёт урезанную картину записи: комментарий
обрезается двумя строками с многоточием, дата выполнения не видна вовсе,
значение собрано в одну компактную строку. Пользователь не может посмотреть
запись целиком, не открывая её на редактирование. Обычный тап по строке
сейчас свободен (длинное нажатие занято контекстным меню) — естественное
место для просмотра деталей. Дизайн уже согласован и зафиксирован в превью
`WorkoutDetailsPreview.kt` (`DetailsCompactDialogVariant` + демо-модели);
файл — временный референс, удаляется после выноса компонента (задача 2.2).

## What Changes

- Обычный тап по `EntryListItemRow` открывает карточку деталей записи
  поверх главного экрана: скругление 28dp, боковые отступы 24dp, по центру
  экрана, фон затемнён скримом (32%, как в референсе).
- Пока детали открыты, исходная строка выделяется как при открытом
  контекстном меню (`isSelected` → `surfaceVariant`), но контекстное меню
  не показывается. После закрытия деталей выделение снимается.
- Содержимое карточки: иконка упражнения, название (`titleLarge`), значение
  крупно (`headlineMedium`, `primary`) в формате «4 х 10 (+ 5 кг)»,
  дата/время (`bodySmall`, `onSurfaceVariant`) — всегда, комментарий —
  целиком (без `maxLines`/`Ellipsis`) в тональном блоке `surfaceVariant`,
  только при наличии.
- Дефолтные значения не показываются: подходы — только при > 1
  (`formatEntryValue` уже так делает), вес — только при > 0 (суффикс «(+ 5 кг)»; строки — по задаче 1.1).
- Закрытие: крестик в правом верхнем углу, тап по скриму, системный Back —
  все три способа эквивалентны, выделение строки снимается.
- Длинное нажатие и контекстное меню работают как раньше — без изменений.
- Компонент карточки выносится из preview-файла в продакшн-код;
  `WorkoutDetailsPreview.kt` перестаёт быть единственным местом жизни
  визуала (детали выноса — в design).
- Данные берутся из уже загруженного `MainUiState.Success.entries` по id —
  без повторного запроса к БД.

## Capabilities

### New Capabilities

_(нет — поведение относится к существующему главному экрану)_

### Modified Capabilities

- `workouts-main-screen`: добавляется требование «Детали записи по тапу на
  строку» — открытие карточки тапом, выделение исходной строки без
  контекстного меню, состав карточки (значение/дата/комментарий целиком,
  скрытие дефолтов), три способа закрытия со снятием выделения.

## Impact

- `ui/screens/main/MainScreen.kt` — тап по строке (добавить `onTap` в
  `detectTapGestures`), транзитное состояние «какая запись открыта»,
  overlay-карточка после `Scaffold` в `MainScreenContent` (скрим накрывает
  FAB/TopAppBar).
- `ui/screens/main/EntryListItemRow.kt` — выделение строки при открытых
  деталях: семантика `Selected` уже есть в `EntryListItemRow`;
  расширяется лямбда `isSelected` в `EntryList` (OR с `detailsEntryId`).
- `ui/screens/main/WorkoutDetailsPreview.kt` — вынос
  `DetailsCompactDialogVariant` и хелперов (`formatDetailDateTime`,
  `detailValueText`, `detailValueWithWeightText`, `DetailComment`) в
  продакшн-код.
- Строковые ресурсы — по задаче 1.1.
- Тесты: JVM-тесты форматтеров до реализации (TDD),
  androidTest главного экрана — полный список по задачам 4.*.
