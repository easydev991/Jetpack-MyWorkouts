## ADDED Requirements

### Requirement: Опциональный номер иконки упражнения

Каждое упражнение каталога (стандартное и пользовательское) SHALL иметь
опциональный номер иконки `iconNumber`: `null` — иконка не назначена,
целое число — номер иконки в будущем наборе ресурсов. Значение SHALL
сохраняться вместе с упражнением и SHALL быть доступно при чтении каталога
без изменений. По умолчанию (новые пользовательские упражнения, prepopulate
стандартного набора) `iconNumber` SHALL быть `null` — MVP не назначает
иконки, номера проставят будущие изменения (ресурсы иконок, назначение
стандартным, выбор в UI). В Room-сущности `ExerciseEntity` поле SHALL
храниться как колонка `icon_number` типа `INTEGER` (nullable) без
SQL DEFAULT — при деструктивном пересоздании схемы (приложение ещё не
в релизе) default не нужен, существующие строки не сохраняются. Номер
иконки в MVP SHALL NOT валидироваться по диапазону: иконки-ресурсы ещё
не существуют, контроль соответствия ресурсам — ответственность будущего
UI-слоя, который будет рендерить иконку.

#### Scenario: Сохранение и чтение номера иконки

- **WHEN** пользовательское упражнение сохраняется с `iconNumber = 5`
- **THEN** при чтении каталога упражнение возвращается с `iconNumber = 5`

#### Scenario: Упражнение без иконки

- **WHEN** пользовательское упражнение сохраняется без указания
  `iconNumber`
- **THEN** при чтении каталога упражнение возвращается с `iconNumber = null`

#### Scenario: Стандартный набор без иконок при prepopulate

- **WHEN** база данных создаётся впервые и стандартный набор предзаполняется
- **THEN** все 13 стандартных упражнений имеют `iconNumber = null`

#### Scenario: Отсутствие иконки и её наличие различимы

- **WHEN** одно упражнение сохранено с `iconNumber = null`, другое —
  с `iconNumber = 0`
- **THEN** при чтении оба значения различимы: `null` и `0`
