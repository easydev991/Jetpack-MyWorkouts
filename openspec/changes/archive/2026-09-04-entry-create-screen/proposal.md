## Why

FAB на главном экране — плейсхолдер, а слой данных для записей о выполнении
уже готов и покрыт тестами (репозиторий, валидация полей, `measuredBy`).
Пользователь не может создать запись из UI — этот change закрывает разрыв
первым реальным сценарием: создание записи о выполнении упражнения.

## What Changes

- FAB на `MainScreen` перестаёт быть плейсхолдером и открывает новый экран
  создания записи.
- Экран создания записи (сверху вниз):
  - выбор упражнения из каталога (выпадающий список);
  - поле «подходы» — только целые числа; при открытии экрана подставлено
    значение 1 (модель данных требует подходы ≥ 1);
  - поле, зависящее от `ExerciseMeasuredBy` выбранного упражнения:
    `REPS` → «повторы» (целые числа), `TIME` → «длительность» (целые числа,
    пикер с шагом 5 секунд, максимум 1 час);
  - дата и время — по умолчанию текущие дата и время устройства;
  - опциональный текстовый комментарий;
  - кнопка сохранения.
- Навигация — по образцу экрана «Оформление»: на экране создания нижняя
  панель навигации скрыта; после сохранения экран закрывается, пользователь
  возвращается назад.
- Экран проектируется с учётом будущего режима редактирования записей;
  в этом change реализуется только режим создания.

## Capabilities

### New Capabilities

- `workout-entry-screen`: экран записи о выполнении — состав полей,
  ветвление по `ExerciseMeasuredBy`, правила ввода (целые числа, шаг
  длительности), поведение при сохранении и навигация. Сформулировано
  neutrally к режиму создания/редактирования; сейчас покрывает создание.

### Modified Capabilities

- `workouts-main-screen`: требование «MainScreen FAB is a placeholder»
  заменяется — FAB открывает экран создания записи (навигация на маршрут
  нового экрана вместо no-op).

## Impact

- `ui/screens/main/MainScreen.kt` — onClick FAB ведёт на новый маршрут
  через колбэк: MainScreen не знает о `NavController` (разделение
  ответственности как у `AppearanceScreen(viewModel, onBackClick)` /
  `RootScreen`).
- `navigation/Screen.kt` — новый маршрут экрана записи.
- `ui/screens/root/RootScreen.kt` — composable нового экрана; скрытие
  нижней панели уже работает через `shouldShowBottomBar` (не-tab маршрут).
- Новые файлы: экран (`ui/screens/entry/`), ViewModel + UiState,
  строковые ресурсы ru/en.
- `data/repository/` — новый интерфейс `WorkoutDataRepository`;
  `RoomWorkoutDataRepository` реализует его без изменения сигнатур
  (чистый рефакторинг под fake-репозиторий в JVM-тестах ViewModel).
- Поведение слоя данных (`workout-data`) не меняется: репозиторий, DAO,
  `EntryValidator` и `measuredBy` уже реализованы и протестированы;
  экран только потребляет их.
- Тесты: Compose UI-тесты по образцу `AppearanceScreenTest`
  (содержимое через state-класс, навигация через NavHost-обёртку).
