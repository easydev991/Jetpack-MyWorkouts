# Spec Delta

## MODIFIED Requirements

### Requirement: Массовый сброс данных

Приложение SHALL предоставлять операцию `deleteAllData`: удаление всех
записей о выполнении, всех упражнений каталога и всех категорий одной
транзакцией БД с последующим восстановлением стандартного набора упражнений
(`isCustom = false`) и стандартного набора из пяти категорий (`PUSH`, `PULL`,
`LEGS`, `CORE`, `CARDIO`, `isCustom = false`, цвета из `StandardCategories` —
значения зафиксированы по `Color.kt` на момент change).
Индивидуальное удаление стандартного упражнения остаётся запрещённым
(требование «Удаление упражнения из каталога»); индивидуальное удаление
стандартной категории остаётся запрещённым (спека `category-data`).
`deleteAllData` — единственная массовая операция, обходящая эти правила,
и запускается только с экрана «Данные приложения» после подтверждения
пользователя. Настройки приложения SHALL NOT затрагиваться.

#### Scenario: Сброс очищает данные и восстанавливает стандартный набор

- **WHEN** `deleteAllData` завершился успешно
- **THEN** записи о выполнении отсутствуют
- **AND** кастомные упражнения отсутствуют
- **AND** стандартный набор упражнений присутствует (`isCustom = false`)
- **AND** кастомные категории отсутствуют
- **AND** стандартный набор из 5 категорий присутствует (`isCustom = false`)

#### Scenario: Сброс атомарен

- **WHEN** во время `deleteAllData` происходит ошибка БД
- **THEN** все данные SHALL остаться в состоянии до операции

### Requirement: Массовый импорт данных

Репозиторий SHALL предоставлять транзакционную операцию
`importData(categories, exercises, entries)`: вставка только переданных
данных, разрешение имени упражнения в id внутри той же транзакции; при любой
ошибке — откат без частичных вставок. Категории из файла SHALL вставляться
в той же транзакции (с сохранением `colorArgb` и `isArchived` как в файле);
упражнения SHALL ссылаться на категории по имени — как существующие в БД,
так и вставленные из файла в этой же транзакции. Дедупликация и валидация
выполняются выше репозитория (use-case); репозиторий отвечает только за
транзакционное хранение. Вставляемые из файла упражнения SHALL получать
id от БД (`autoGenerate`); значение `isArchived` импортируемого
упражнения SHALL сохраняться как есть (если импортируется архивное —
оно остаётся архивным в новом экземпляре БД).

#### Scenario: Импорт откатывается при сбое

- **WHEN** во время `importData` вставка завершается ошибкой
- **THEN** в БД нет изменений из этого импорта

#### Scenario: Импорт разрешает имена в id

- **WHEN** импортируемая запись ссылается на упражнение по имени
- **THEN** внутри транзакции запись связывается с id существующего либо
  вставленного упражнения

#### Scenario: Импорт сохраняет isArchived

- **WHEN** импортируется упражнение с `isArchived = true`
- **THEN** в БД упражнение сохраняется с `isArchived = true`
  (импорт архивного упражнения остаётся архивным)

#### Scenario: Упражнение ссылается на категорию из файла

- **WHEN** импортируемое упражнение ссылается на категорию, которой нет в БД,
  но она есть в переданном списке категорий
- **THEN** внутри транзакции категория вставляется, и упражнение ссылается
  на неё по имени

### Requirement: Снимки каталога и записей

Репозиторий SHALL предоставлять разовые снимки данных: `getAllExercises`
— ВСЕ упражнения каталога (стандартные, кастомные, активные и
архивные — без фильтрации по `isArchived`), `getAllEntries` — все
записи о выполнении, `getAllCategories` — все категории (активные и
архивные; контракт — спека `category-data`, требование «Снимок всех
категорий»). `getAllExercises()` и `getAllCategories()` используются для
экспорта резервной копии (`app-data-management`) и дедупликации импорта:
архивные упражнения и категории включаются в снимок, чтобы при импорте
в новый экземпляр БД сохранялся весь набор. Восстановление архивного
состояния пользователя — задача use-case импорта; репозиторий возвращает
данные как есть.

#### Scenario: Снимок возвращает полный каталог

- **WHEN** вызван `getAllExercises` при непустом каталоге
- **THEN** возвращены все упражнения — стандартные и кастомные

#### Scenario: Снимок включает архивные упражнения

- **WHEN** в каталоге есть и активные, и архивные упражнения
- **THEN** `getAllExercises()` возвращает и активные, и архивные
  в едином списке (с `isArchived` каждого упражнения)

#### Scenario: Снимок включает все категории

- **WHEN** в БД есть активные и архивные категории
- **THEN** `getAllCategories()` возвращает их в едином списке
  (с `colorArgb` и `isArchived` каждой категории)
