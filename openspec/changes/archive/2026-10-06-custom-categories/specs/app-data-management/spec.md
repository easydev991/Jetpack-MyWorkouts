# Spec Delta

## MODIFIED Requirements

### Requirement: Создание резервной копии

Кнопка «Создать резервную копию» / "Create backup" SHALL выгружать все
упражнения, все категории и все записи о тренировках в JSON-файл через
системный выбор места сохранения (SAF) с mime-типом `application/json`.
Предлагаемое имя файла SHALL иметь вид `myworkouts-backup-<yyyy-MM-dd>.json`,
где `<yyyy-MM-dd>` — текущая дата. Кнопка SHALL быть скрыта, если в
приложении нет данных для экспорта: ни одной записи, ни одного
кастомного упражнения и ни одной кастомной категории
(стандартный набор упражнений и категорий предзаполняется всегда и сам по
себе данными пользователя не считается; правки стандартных упражнений
данными пользователя не считаются). Пока выполняется любая из трёх
операций, кнопка SHALL быть недоступна. Результат — Toast об успехе
или ошибке.

#### Scenario: Успешный экспорт

- **WHEN** в приложении есть записи и пользователь выбирает место
  сохранения
- **THEN** в выбранное место записывается JSON-файл резервной копии
- **AND** показывается Toast об успешном создании резервной копии

#### Scenario: Нет данных — кнопки скрыты

- **WHEN** в приложении нет ни записей о тренировках, ни кастомных
  упражнений, ни кастомных категорий (только стандартные наборы)
- **THEN** кнопки «Создать резервную копию» и «Удалить все данные» скрыты
- **AND** кнопка «Восстановить из резервной копии» остаётся видимой

#### Scenario: Только пользовательские упражнения — экспорт доступен

- **WHEN** записей нет, но есть хотя бы одно кастомное упражнение
- **THEN** кнопка «Создать резервную копию» видима
- **AND** экспорт создаёт файл со списком упражнений и пустым массивом
  записей

#### Scenario: Только кастомная категория — экспорт доступен

- **WHEN** записей и кастомных упражнений нет, но есть хотя бы одна
  кастомная категория
- **THEN** кнопка «Создать резервную копию» видима
- **AND** экспорт создаёт файл с категориями и пустыми массивами упражнений
  и записей

#### Scenario: Кнопка недоступна во время экспорта

- **WHEN** экспорт выполняется
- **THEN** кнопка «Создать резервную копию» недоступна для нажатия
- **AND** прогресс-индикатор не показывается

### Requirement: Формат файла резервной копии

Резервная копия SHALL быть JSON-объектом
`{ "version": 1, "exercises": [...], "categories": [...], "entries": [...],
"settings": {...} }`,
где `version` — версия формата. Каждый элемент `exercises` SHALL содержать
поля упражнения: `name`, `category` (имя категории — String), `measuredBy`,
`isCustom`, `comment` (опционально), `iconNumber` (опционально),
`createdAt`, `isArchived`. Каждый элемент `categories` SHALL содержать поля
категории: `name` (String), `colorArgb` (Int), `isArchived` (Boolean,
пишется всегда как `true`/`false`); поле `isCustom` в файл SHALL NOT
писаться (значение из файла игнорируется при импорте — файл недоверенный).
Каждый элемент `entries` SHALL содержать поля записи: `exerciseName`,
`date`, `sets`, `reps` (опционально), `weightKg` (опционально),
`durationSec` (опционально), `comment` (опционально), `createdAt`.
Блок `settings` SHALL писаться всегда и содержать настройки видимости
вкладок обзора: `overviewTabVisibility` (карта имя-вкладки → Boolean) и
`lastOverviewTab` (String); контракт включения в копию и применения при
восстановлении — канон спеки `overview-screen` (требование «Экран
настроек видимости вкладок»); файл без блока `settings` (бэкапы до его
введения) SHALL оставаться валидным — при импорте состояние настроек
SHALL NOT меняться.
Идентификаторы строк базы данных в файле SHALL NOT храниться: связь
«запись → упражнение» выражается именем упражнения (`exerciseName` →
`name`), связь «упражнение → категория» — именем категории
(`exercises[].category` → `categories[].name` либо категории текущей БД).
Поле `modifiedAt` в файле SHALL NOT храниться: восстановленная запись
SHALL получать `modifiedAt`, равный моменту импорта. Файл SHALL быть
отформатирован человекочитаемо (с отступами). Типы полей строгие:
`version` — Int; `date` и `createdAt` — Long (миллисекунды эпохи);
`sets`, `reps`, `durationSec`, `iconNumber`, `colorArgb` — Int; `weightKg`
— Double; `isCustom`, `isArchived` — Boolean; строки (`name`, `category`,
`measuredBy`, `exerciseName`, `comment`) — String. «(опционально)»
означает: поле может отсутствовать или быть `null`; при наличии — строго
указанный тип, иначе файл ошибочен. `isArchived` SHALL писаться в файл
всегда как `true` или `false` (в `exercises` и в `categories`), SHALL NOT
отсутствовать и SHALL NOT быть `null`. `iconNumber` тоже пишется всегда,
но допускает значение `null`. Версия формата: экспорт SHALL писать `1`;
импорт SHALL принимать `1` и `2` — файлы с меткой `2` создаёт код
существующих релизов, они остаются читаемыми (Design Decision 9).
`categories` — обратно совместимое расширение. Файл, созданный до введения
`categories` (без этого массива), SHALL оставаться валидным — при его
импорте упражнения резолвят категории только по текущей БД. Чтение нового
файла старой версией приложения вне скоупа этого изменения и уже покрыто
гарантией «Неизвестные поля игнорируются» (требование «Обработка ошибок
восстановления»).

#### Scenario: Структура файла

- **WHEN** резервная копия создана
- **THEN** файл начинается с объекта, содержащего `"version": 1`, массивы
  `exercises`, `categories`, `entries` и блок `settings`
- **AND** записи ссылаются на упражнения по имени, упражнения — на
  категории по имени, без идентификаторов БД

#### Scenario: Блок настроек в файле

- **WHEN** резервная копия экспортируется при выключенной вкладке «Рекорды»
  и последней вкладке «Активность»
- **THEN** блок `settings` содержит `overviewTabVisibility` с
  `"RECORDS": false` и `lastOverviewTab = "ACTIVITY"`
- **AND** файл без блока `settings` (старый бэкап) импортируется успешно
  без изменения настроек устройства

#### Scenario: Категории в файле

- **WHEN** резервная копия экспортируется при наличии кастомной категории
  «Спина» с `colorArgb = 0xFF4E6EF2`
- **THEN** массив `categories` содержит все категории БД (активные и
  архивные), включая элемент с `"name": "Спина"`, `"colorArgb"` — Int ARGB
  этой категории, `"isArchived": false`, и пять стандартных категорий

#### Scenario: Старый файл без категорий импортируется

- **WHEN** импортируется валидный файл версии 1 без массива `categories`
  (бэкап, сделанный до введения поля)
- **THEN** импорт завершается успешно
- **AND** упражнения резолвят категории по текущей БД; упражнение с
  категорией, отсутствующей в БД, пропускается

#### Scenario: Опциональные поля

- **WHEN** у упражнения или записи нет комментария/веса/длительности
- **THEN** соответствующее поле отсутствует или равно `null` в файле

#### Scenario: Номер иконки в файле

- **WHEN** резервная копия экспортируется
- **THEN** каждый элемент `exercises` содержит поле `iconNumber`:
  целое число либо `null`, если у упражнения нет иконки
  (поле пишется всегда, даже как `null`; «(опционально)» в списке —
  про допустимость старых файлов при импорте)

#### Scenario: Старый файл без номера иконки импортируется

- **WHEN** импортируется валидный файл версии 1, элементы `exercises`
  которого не содержат `iconNumber` (бэкап, сделанный до введения поля)
- **THEN** импорт завершается успешно
- **AND** упражнениям из файла присваивается `iconNumber = null`

#### Scenario: Признак архивации в файле

- **WHEN** резервная копия экспортируется
- **THEN** каждый элемент `exercises` и `categories` содержит поле
  `isArchived`: `true` — если сущность архивная, `false` — если активная
  (поле пишется всегда)

#### Scenario: Старый файл без признака архивации импортируется

- **WHEN** импортируется валидный файл версии 1, элементы `exercises`
  которого не содержат `isArchived` (бэкап, сделанный до введения поля)
- **THEN** импорт завершается успешно
- **AND** упражнениям из файла присваивается `isArchived = false`

### Requirement: Восстановление из резервной копии слиянием

Кнопка «Восстановить из резервной копии» / "Restore from backup" SHALL
открывать системный выбор файла (SAF) без ограничения mime-типа. Выбранный
файл SHALL сливаться с текущими данными: ничего не перезаписывается,
добавляется только недостающее. Дедупликация: упражнения — по имени (без
учёта регистра), категории — по `name.trim().lowercase()`, записи — по
содержимому (имя упражнения, дата, подходы, повторы, вес, длительность,
комментарий). Категории из файла SHALL создаваться при отсутствии
(сохраняя `colorArgb` и `isArchived` из файла; вставляемые получают
`isCustom = true` — файл недоверенный; стандартные категории всегда есть
в БД и дедупятся). При дедупликации категории по имени существующая
категория SHALL NOT изменяться, кроме одностороннего применения
архивации: если в файле `isArchived = true`, а существующая активна — она
перемещается в архив; обратная разархивация SHALL NOT выполняться
(симметрично правилу упражнений). `colorArgb` существующей категории при
дедупликации остаётся прежним. Связь упражнения с категорией
восстанавливается по имени: используется существующая в БД категория либо
вставленная из файла. Упражнение, категория которого не найдена ни в
файле, ни в текущей БД, SHALL быть пропущено без провала всего импорта
(по аналогии с записями без упражнения). Записи, упражнение для которых
не найдено ни в файле, ни в текущем каталоге, SHALL быть пропущены без
провала всего импорта. Записи, не прошедшие валидацию (например,
количество подходов меньше 1 или несовместимый с типом измерения
упражнения набор полей), SHALL быть пропущены так же. Вставляемые из
файла упражнения SHALL получать `isCustom = true`: значение `isCustom`
из файла игнорируется. Вставляемое из файла упражнение SHALL сохранять
свой `iconNumber` и `isArchived` из файла как есть (в т.ч. `true`, чтобы
попасть в архив при импорте). Диалог подтверждения импорта SHALL NOT
показываться: merge только добавляет и архивирует. Результат — Toast
об успехе или ошибке. Повторный импорт того же файла SHALL быть
идемпотентным (дедупликация упражнений, категорий и записей).

#### Scenario: Успешное слияние

- **WHEN** выбран корректный файл резервной копии
- **THEN** категории и упражнения из файла, которых нет в БД, добавляются
- **AND** записи из файла, дубликатов которых нет, добавляются
- **AND** существующие данные не изменяются, кроме архивации по
  одностороннему правилу
- **AND** показывается Toast об успешном восстановлении

#### Scenario: Дубликаты пропускаются

- **WHEN** категория или упражнение с тем же именем уже есть в БД
- **THEN** новая сущность не создаётся
- **AND** когда запись с тем же содержимым уже есть в базе
- **THEN** дубликат записи не вставляется

#### Scenario: Категория из файла создаётся при отсутствии

- **WHEN** в файле есть категория «Спина», которой нет в БД
- **THEN** категория вставляется с `colorArgb` и `isArchived` из файла
  AND `isCustom = true`

#### Scenario: Упражнение с неизвестной категорией пропускается

- **WHEN** упражнение из файла ссылается на категорию, которой нет ни
  в файле, ни в текущей БД
- **THEN** это упражнение пропускается, остальные сущности файла
  импортируются
- **AND** записи, ссылающиеся на это упражнение по имени, тоже
  пропускаются

#### Scenario: Архивация существующей категории из файла применяется

- **WHEN** категория из файла дедуплицируется по имени с существующей
  активной AND в файле у неё `isArchived = true`
- **THEN** существующая категория перемещается в архив

#### Scenario: Разархивация существующей категории из файла не выполняется

- **WHEN** категория из файла дедуплицируется с существующей архивной
  AND в файле у неё `isArchived = false`
- **THEN** существующая категория остаётся в архиве

#### Scenario: Цвет существующей категории не меняется

- **WHEN** категория из файла дедуплицируется с существующей
- **THEN** существующая категория остаётся со своим прежним `colorArgb`

#### Scenario: Номер иконки вставленного упражнения сохраняется

- **WHEN** упражнение из файла вставляется в каталог (имени нет в каталоге)
- **THEN** вставленное упражнение получает `iconNumber` из файла

#### Scenario: Номер иконки существующего упражнения при дедупликации не меняется

- **WHEN** упражнение из файла дедуплицируется по имени с существующим
- **THEN** существующее упражнение остаётся со своим прежним `iconNumber`

#### Scenario: Запись без упражнения пропускается

- **WHEN** запись ссылается на имя упражнения, которого нет ни в файле,
  ни в текущем каталоге
- **THEN** эта запись пропускается, остальные записи файла импортируются

#### Scenario: Признак архивации вставленного упражнения сохраняется

- **WHEN** упражнение из файла с `isArchived = true` вставляется в каталог
- **THEN** вставленное упражнение получает `isArchived = true` и попадает
  в архив

#### Scenario: Архивация существующего упражнения из файла применяется

- **WHEN** упражнение из файла дедуплицируется по имени с существующим
  AND в файле у него `isArchived = true` AND существующее упражнение
  активно
- **THEN** существующее упражнение перемещается в архив

#### Scenario: Разархивация существующего упражнения из файла не выполняется

- **WHEN** упражнение из файла дедуплицируется по имени с существующим
  AND в файле у него `isArchived = false` AND существующее упражнение
  архивное
- **THEN** существующее упражнение остаётся в архиве (значение из файла
  игнорируется)

#### Scenario: Идемпотентность повторного импорта

- **WHEN** один и тот же файл импортируется дважды
- **THEN** после второго импорта категории, упражнения и записи не
  дублируются

### Requirement: Обработка ошибок восстановления

Битый или несовместимый файл SHALL приводить к Toast с обобщённым
локализованным сообщением об ошибке (ru/en); технические детали ошибки
пользователю SHALL NOT показываться — они попадают в лог. Данные
приложения SHALL NOT меняться. Ошибочными считаются:
нечитаемый JSON; отсутствие или неверный тип полей `version`,
`exercises`, `entries`; отсутствие или неверный тип поля `name` у
элемента `categories` (если массив присутствует) или неверный тип
`colorArgb`/`isArchived` у элемента `categories`; неподдерживаемая версия
формата; элемент массива `exercises`/`entries` без обязательных полей или
с неверным типом значения; неизвестное значение `measuredBy` где-либо в
файле. Неизвестное значение категории (`exercises[].category`) ошибкой
файла SHALL NOT считаться: такое упражнение пропускается (требование
«Восстановление из резервной копии слиянием»). Неизвестные поля в
объектах SHALL игнорироваться без ошибки.

#### Scenario: Битый JSON

- **WHEN** выбран файл, не являющийся корректным JSON
- **THEN** показывается Toast с ошибкой
- **AND** данные приложения не изменились

#### Scenario: Неподдерживаемая версия формата

- **WHEN** файл содержит `"version"`, отличный от поддерживаемых версий
  (поддерживаемые — `1` и `2`)
- **THEN** показывается Toast с ошибкой о несовместимом файле
- **AND** данные приложения не изменились

#### Scenario: Неизвестные поля игнорируются

- **WHEN** объекты файла содержат поля, не входящие в формат резервной
  копии
- **THEN** импорт выполняется успешно, неизвестные поля игнорируются

#### Scenario: Категория упражнения с произвольной строкой

- **WHEN** файл содержит упражнение с `category = "Старая категория"`,
  которой нет ни в `categories` файла, ни в БД
- **THEN** файл НЕ отвергается
- **AND** упражнение пропускается, остальной импорт продолжается
