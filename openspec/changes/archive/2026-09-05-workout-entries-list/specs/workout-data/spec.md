# workout-data Дельта

## MODIFIED Requirements

### Requirement: Валидация полей записи

Хранилище SHALL отклонять запись о выполнении, если: количество подходов
меньше 1; повторы указаны и меньше 1; вес указан и меньше 0; длительность
указана и меньше 1; повторы и длительность заданы одновременно; запись
привязана к тренировке (workoutId ≠ null — тренировки появятся в
будущих изменениях). Дополнительно запись SHALL отклоняться, если
обязательное по типу измерения упражнения (`measuredBy`)
значение отсутствует: для `REPS` — повторы не заданы, для `TIME` —
длительность не задана. Идентичные записи (одно упражнение
и одинаковые параметры) SHALL быть разрешены: дедупликация SHALL NOT
выполняться, каждая вставка создаёт отдельную строку со своим id.
Обнуляемость полей на уровне модели SHALL
сохраняться (несоответствие ловится валидацией, не типом); отсутствие
веса (собственный вес) и нулевой вес SHALL оставаться различимыми
состояниями.

#### Scenario: Нулевое количество подходов

- **WHEN** выполняется попытка сохранить запись с подходами = 0
- **THEN** операция завершается ошибкой
- **AND** запись не создаётся

#### Scenario: Привязка к тренировке отклоняется

- **WHEN** выполняется попытка сохранить запись с workoutId ≠ null
- **THEN** операция завершается ошибкой
- **AND** запись не создаётся

#### Scenario: Отсутствие веса и нулевой вес различимы

- **WHEN** одна запись сохранена без веса, другая — с весом 0.0
- **THEN** при чтении обе записи различимы: у первой вес не задан,
  у второй равен 0.0

#### Scenario: Отсутствие повторов у упражнения на повторы

- **WHEN** сохраняется запись упражнения `measuredBy = REPS`
  без повторов (даже если длительность указана)
- **THEN** операция завершается ошибкой
- **AND** запись не создаётся

#### Scenario: Нулевое количество повторов отклоняется

- **WHEN** сохраняется запись с заданными повторами = 0
- **THEN** операция завершается ошибкой
- **AND** запись не создаётся

#### Scenario: Несовместимые поля отклоняются

- **WHEN** сохраняется запись с одновременно заданными повторами
  и длительностью
- **THEN** операция завершается ошибкой
- **AND** запись не создаётся

#### Scenario: Отсутствие длительности у упражнения на время

- **WHEN** сохраняется запись упражнения `measuredBy = TIME`
  без длительности
- **THEN** операция завершается ошибкой
- **AND** запись не создаётся

#### Scenario: Нулевая длительность отклоняется

- **WHEN** сохраняется запись упражнения `measuredBy = TIME`
  с длительностью = 0
- **THEN** операция завершается ошибкой
- **AND** запись не создаётся

#### Scenario: Повторяющиеся записи сохраняются отдельно

- **WHEN** сохраняются две записи с одним упражнением и одинаковыми
  параметрами (подходы, повторы/длительность, вес)
- **THEN** обе записи успешно сохраняются отдельными строками
  со своими идентификаторами
- **AND** обе отображаются в списке записей

### Requirement: Поддержка упражнений «на время»

Запись о выполнении SHALL поддерживать упражнения «на время»: повторы не
заданы, длительность в секундах задана. Длительность SHALL сохранять
переданное значение как есть (валидность ≥ 1 — см. «Валидация полей
записи»). Соответствие заполненных полей типу упражнения SHALL
обеспечиваться валидацией записи: запись упражнения `measuredBy = TIME`
SHALL содержать длительность, `measuredBy = REPS` — повторы. Запись
SHALL содержать только обязательное по `measuredBy` поле — повторы
и длительность не могут быть заданы одновременно (см. «Валидация
полей записи»). Хранение и чтение `measuredBy` — см. требование
«Единый каталог для стандартных и пользовательских упражнений».

#### Scenario: Сохранение планки

- **WHEN** сохраняется запись «планка, 1 подход, 60 секунд»
  без повторов и веса
- **THEN** запись сохранена с длительностью = 60 и незаданными повторами

#### Scenario: Слой данных не навязывает соответствие

- **WHEN** сохраняется запись со ссылкой на упражнение
  `measuredBy = REPS`, у которой повторы не заданы, а длительность задана
- **THEN** операция завершается ошибкой: валидация записи требует
  повторы для `REPS` и длительность для `TIME`
- **AND** запись не создаётся

## ADDED Requirements

### Requirement: Реактивный список записей

Слой данных SHALL предоставлять реактивный список всех записей о
выполнении (`Flow`), актуализирующийся при изменении таблицы записей.
Каждый элемент списка SHALL содержать идентификатор записи, название
упражнения каталога (по ссылке `exerciseId`), количество подходов,
повторы (если заданы), длительность в секундах (если задана) и дату/время
записи. Список SHALL быть упорядочен по дате/времени записи убыванием
(новые первыми).

#### Scenario: Пустое хранилище

- **WHEN** в хранилище нет записей
- **THEN** реактивный список эммитит пустой список

#### Scenario: Название упражнения в элементе списка

- **WHEN** запись ссылается на упражнение каталога
- **THEN** элемент списка содержит название этого упражнения

#### Scenario: Сортировка новых первыми

- **WHEN** в хранилище есть записи с разными датами
- **THEN** список упорядочен по дате/времени убыванием

#### Scenario: Список актуализируется при изменениях

- **WHEN** запись добавляется или удаляется
- **THEN** подписчик реактивного списка получает обновлённый список
