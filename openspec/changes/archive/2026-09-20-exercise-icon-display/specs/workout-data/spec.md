# workout-data Delta

## MODIFIED Requirements

### Requirement: Опциональный номер иконки упражнения

Каждое упражнение каталога (стандартное и пользовательское) SHALL иметь
опциональный номер иконки `iconNumber`: `null` — иконка не назначена,
целое число — номер в стабильной таблице иконок (1..19, номера не зависят
от имён ресурсов). Значение SHALL сохраняться вместе с упражнением и
SHALL быть доступно при чтении каталога без изменений. По умолчанию
`iconNumber` SHALL быть `null` для новых пользовательских упражнений —
номер назначается только при явном указании (UI выбора иконки — вне
скопа). Prepopulate стандартного набора SHALL назначать номера иконок
всем 13 стандартным упражнениям по фиксированному соответствию
(номер — упражнение): 13 — подтягивания, 14 — австралийские подтягивания,
18 — приседания, 15 — отжимания, 16 — отжимания с колен, 12 — выпады,
7 — брусья, 15 — планка (осознанное переиспользование: отдельной иконки
планки нет, планка попадает в группу push/core-статики), 8 — скручивания,
1 — подъёмы ног в висе, 19 — приседания на одной ноге, 17 — бег,
11 — скакалка. В Room-сущности `ExerciseEntity` поле SHALL храниться
как колонка `icon_number` типа `INTEGER` (nullable) без SQL DEFAULT —
при деструктивном пересоздании схемы (приложение ещё не в релизе) default
не нужен, существующие строки не сохраняются. Номер иконки SHALL NOT
валидироваться по диапазону в слое данных: контроль соответствия ресурсам
— ответственность UI-слоя, который рендерит иконку (неизвестный номер —
тихий fallback «без иконки»).

#### Scenario: Сохранение и чтение номера иконки

- **WHEN** пользовательское упражнение сохраняется с `iconNumber = 5`
- **THEN** при чтении каталога упражнение возвращается с `iconNumber = 5`

#### Scenario: Упражнение без иконки

- **WHEN** пользовательское упражнение сохраняется без указания
  `iconNumber`
- **THEN** при чтении каталога упражнение возвращается с `iconNumber = null`

#### Scenario: Стандартный набор без иконок при prepopulate

- **WHEN** база данных создаётся впервые и стандартный набор предзаполняется
- **THEN** все 13 стандартных упражнений имеют ненулевой `iconNumber`
  согласно фиксированному соответствию, заданному в теле Requirement

#### Scenario: Отсутствие иконки и её наличие различимы

- **WHEN** одно упражнение сохранено с `iconNumber = null`, другое —
  с `iconNumber = 0`
- **THEN** при чтении оба значения различимы: `null` и `0`

### Requirement: Реактивный список записей

Слой данных SHALL предоставлять реактивный список всех записей о
выполнении (`Flow`), актуализирующийся при изменении таблицы записей.
Каждый элемент списка SHALL содержать идентификатор записи, название
упражнения каталога (по ссылке `exerciseId`), номер иконки упражнения
(`iconNumber` — подтягивается тем же JOIN на таблицу `exercises`),
количество подходов, повторы (если заданы), длительность в секундах
(если задана) и дату/время записи. Список SHALL быть упорядочен по
дате/времени записи убыванием (новые первыми).

#### Scenario: Пустое хранилище

- **WHEN** в хранилище нет записей
- **THEN** реактивный список эммитит пустой список

#### Scenario: Название упражнения в элементе списка

- **WHEN** запись ссылается на упражнение каталога
- **THEN** элемент списка содержит название этого упражнения

#### Scenario: Номер иконки в элементе списка

- **WHEN** запись ссылается на упражнение с назначенным `iconNumber`
  (например, подтягивания, 13)
- **THEN** элемент списка содержит этот `iconNumber`
- **AND** запись упражнения с `iconNumber = null` возвращает элемент
  с `iconNumber = null`

#### Scenario: Сортировка новых первыми

- **WHEN** в хранилище есть записи с разными датами
- **THEN** список упорядочен по дате/времени убыванием

#### Scenario: Список актуализируется при изменениях

- **WHEN** запись добавляется или удаляется
- **THEN** подписчик реактивного списка получает обновлённый список
