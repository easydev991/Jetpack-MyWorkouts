## Why

Все данные пользователя (упражнения и записи о тренировках) живут только в
локальной Room-базе: переустановка приложения, смена устройства или очистка
данных уничтожают их безвозвратно. Нужен управляемый способ вынести данные
наружу, вернуть их обратно и начать с чистого листа.

## What Changes

- На экран «Ещё» добавляется кнопка «Данные приложения» (по образцу кнопки
  «Оформление приложения»), ведущая на новый одноимённый экран.
- Новый экран «Данные приложения» — не таб (нижняя панель скрывается,
  есть возврат назад), три действия:
  - **Создать резервную копию** — выгрузка всех упражнений и записей в
    JSON-файл через SAF (`ActivityResultContracts.CreateDocument`),
    предлагаемое имя `myworkouts-backup-<yyyy-MM-dd>.json`. Кнопка скрыта,
    если нет данных для экспорта (ни записей, ни пользовательских
    упражнений); недоступна во время экспорта.
  - **Восстановить из резервной копии** — выбор файла через SAF
    (`OpenDocument`), парсинг и слияние с текущими данными (merge, ничего
    не перезаписывается). Битый или несовместимый файл — сообщение об
    ошибке, данные не меняются.
  - **Удалить все данные** — кнопка в цвет ошибки, `AlertDialog`
    подтверждения. Удаляются все записи и упражнения, затем заново
    предзаполняется стандартный набор упражнений. Настройки (тема,
    динамические цвета) не
    трогаются. После удаления экран реактивно скрывает кнопки экспорта
    и удаления.
- Результат каждой операции — Toast (успех/ошибка); во время операции
  все три кнопки недоступны, параллельные операции запрещены;
  прогресс-индикаторов нет.
- Новые методы `WorkoutDataRepository`: снимок всех упражнений и записей,
  массовая вставка, `deleteAllData()`; реализация в
  `RoomWorkoutDataRepository` + новые DAO-методы, удаление и вставка —
  транзакционно.
- Новый слой `domain/usecase/`: `ExportBackupUseCase`, `ImportBackupUseCase` — `Result<T>`, `try/catch`, свои исключения
  (`BackupException` + типизированный `BackupError`) с русскими сообщениями, файловый I/O на
  `Dispatchers.IO`.
- Формат резервной копии — собственный JSON
  `{ "version": 1, "exercises": [...], "entries": [...] }`, сериализация
  через `org.json` (Android stdlib, без новых зависимостей).
- Маршрут `Screen.AppData ("app_data")` в `navigation/Screen.kt`;
  `AppDataViewModel` через companion `factory(...)`;   `AppDataUiState`
  с `hasData`, `isBusy` и `result` (типизированный исход
  операции); `clearResult()` — метод ViewModel.
- Строки ru (значения по умолчанию) + en; preview светлая + тёмная, ru.

## Capabilities

### New Capabilities

- `app-data-management`: управление данными приложения — экспорт резервной
  копии в JSON через SAF, восстановление слиянием из резервной копии,
  удаление всех данных с повторным предзаполнением стандартных упражнений;
  формат резервной копии, стратегия merge/дедупликации и обработка ошибок.

### Modified Capabilities

- `more-screen`: добавляется кнопка «Данные приложения», навигация на новый
  экран `Screen.AppData`.
- `non-tab-screen-navigation`: в перечень зарегистрированных назначений
  `RootScreen` добавляется `Screen.AppData` (не таб).
- `workout-data`: репозиторий расширяется снимками (`getAllExercises`,
  `getAllEntries`), транзакционным `importData` и массовым сбросом
  `deleteAllData` с восстановлением стандартного набора — явное
  переопределение архивного решения «bulk-удаление — YAGNI»
  (2026-09-02-workout-data-deletion); индивидуальное удаление стандартных
  упражнений остаётся запрещённым.

## Impact

- **Код**: `navigation/Screen.kt` (новый маршрут), `ui/screens/root/RootScreen.kt`
  (composable-destination), `ui/screens/more/MoreScreen.kt` (кнопка), новые
  `ui/screens/appdata/`, `ui/state/AppDataUiState.kt`,
  `ui/viewmodel/AppDataViewModel.kt`, новый слой `domain/usecase/`,
  `WorkoutDataRepository` + `RoomWorkoutDataRepository` + `ExerciseDao` /
  `ExerciseEntryDao` (снимки, массовая вставка, удаление, транзакции).
- **Зависимости**: runtime-зависимости не добавляются — SAF, `org.json`,
  Room и Compose уже в проекте; единственная новая — test-зависимость
  `org.json:json` для JVM unit-тестов (design Decision 1); разрешений в
  манифесте не требуется.
- **Тесты**: unit — use-cases (формат экспорта, дедупликация, битый файл,
  восстановление связей) и `AppDataViewModel`; androidTest — кнопка на
  «Ещё» и экран; оба fake-репозитория JVM-тестов (`MainViewModelFakeRepository`,
  `FakeWorkoutDataRepository`) расширяются новыми методами.
- **Данные**: формат резервной копии версионирован (`version: 1`), БД-схема
  не меняется.
