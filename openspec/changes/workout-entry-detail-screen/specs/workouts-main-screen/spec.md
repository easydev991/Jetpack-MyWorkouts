# Spec Delta

## REMOVED Requirements

### Requirement: Детали записи по тапу на строку

**Reason**: Всплывающая карточка деталей (`DetailsOverlay` со скримом,
compose-локальное состояние, собственный `BackHandler`) заменена отдельным
навигационным экраном деталей записи. Тап по строке сохранён, но теперь
открывает экран, а не карточку поверх списка.

**Migration**: Открытие по тапу, пункт «Просмотр» меню и a11y-действие
«Показать детали» — в новой capability `workout-entry-detail-screen`, требование
«Открытие экрана деталей записи». Выделение строки осталось только у
контекстного меню (сценарий «Строка записи визуально выделяется при показе
меню» требования «Удаление записи длинным нажатием»); сценарии
авто-закрытия/актуализации попапа покрыты состояниями и реактивным потоком
детального экрана (требования «Состояния экрана и несуществующий id»,
«Актуализация данных экрана» в `workout-entry-detail-screen`).

### Requirement: Содержимое карточки деталей записи

**Reason**: Компонент карточки `EntryDetailsCard` удаляется вместе с
попап-механизмом; содержимое деталей переезжает на полноэкранную компоновку
варианта A2 (контент по центру без Card-фона).

**Migration**: Состав и стили контента — в новой capability
`workout-entry-detail-screen`, требование «Состав экрана деталей записи» (иконка,
название, значение с весовым суффиксом, дата/время, комментарий в тональном
блоке — правила сохранены).

## MODIFIED Requirements

### Requirement: Удаление записи длинным нажатием

Длинное нажатие на строку записи SHALL открывать контекстное меню в точке
нажатия с пунктами «Просмотр», «Изменить» и «Удалить» («Просмотр» — выше
«Изменить», «Изменить» — выше «Удалить»). Выбор «Просмотр» SHALL открывать
детальный экран записи (capability `workout-entry-detail-screen`) — тот же
навигационный переход, что обычный тап по строке. Выбор «Удалить» SHALL
открывать алерт подтверждения: подтверждение SHALL удалять запись через слой
данных, отмена SHALL закрывать алерт без удаления; закрытие без выбора SHALL
закрывать меню и алерт без действий. Каждая строка записи SHALL также
предоставлять accessibility-действие «Открыть меню».

#### Scenario: Длинное нажатие открывает меню с пунктом «Удалить»

- **WHEN** пользователь выполняет длинное нажатие на строку записи
- **THEN** открывается контекстное меню
- **AND** меню содержит пункт «Просмотр» выше пункта «Изменить»
- **AND** меню содержит пункт «Изменить» выше пункта «Удалить»
- **AND** меню содержит пункт «Удалить»

#### Scenario: Пункт «Просмотр» открывает экран деталей

- **WHEN** пользователь выбрал пункт «Просмотр» контекстного меню
- **THEN** открывается детальный экран этой записи (поведение — capability
  `workout-entry-detail-screen`)

#### Scenario: Accessibility-действие строки открывает то же меню

- **WHEN** пользователь скринридера активирует на строке записи
  accessibility-действие «Открыть меню»
- **THEN** открывается то же контекстное меню с пунктами «Просмотр»,
  «Изменить» и «Удалить»
- **AND** выбор пунктов меню работает как при открытии долгим нажатием

#### Scenario: Контекстное меню позиционируется в точке нажатия

- **WHEN** пользователь выполняет длинное нажатие на строку записи
  в координатах (x, y) относительно строки
- **THEN** DropdownMenu позиционируется так, что его top-left
  совпадает с точкой касания

#### Scenario: Строка записи визуально выделяется при показе меню

- **WHEN** пользователь выполняет длинное нажатие на строку записи
- **THEN** строка записи визуально выделяется (фон отличается от
  обычных строк)
- **AND** выделение пропадает, когда контекстное меню закрывается
  (тап вне меню, выбор пункта, системная отмена)

#### Scenario: Подтверждение удаления удаляет запись

- **WHEN** пользователь выбрал «Удалить» и подтвердил удаление в алерте
- **THEN** запись удаляется из хранилища
- **AND** запись исчезает из списка

#### Scenario: Отмена удаления сохраняет запись

- **WHEN** пользователь выбрал «Удалить» и нажал «Отмена» в алерте
- **THEN** алерт закрывается
- **AND** запись остаётся в списке

#### Scenario: Пункты меню и их иконки

- **WHEN** контекстное меню строки записи открыто
- **THEN** каждый пункт имеет ведущую иконку: «Просмотр», карандаш у
  «Изменить», корзина у «Удалить» (конкретная иконка пункта «Просмотр»
  выбирается при реализации)
- **AND** иконки SHALL NOT иметь собственного текстового описания
  (пункт читается по тексту)

#### Scenario: Accessibility-открытие меню

- **WHEN** пользователь скринридера (TalkBack) активирует на строке
  локализованное accessibility-действие «Открыть меню» / "Open menu" из
  меню действий
- **THEN** открывается то же контекстное меню
- **AND** точка касания отсутствует — позиция меню по умолчанию (центр
  строки) SHALL допускаться
