## ADDED Requirements

### Requirement: Список записей разделён на секции по дате

Список записей на главном экране SHALL быть разделён на визуальные
секции по календарной дате записи: каждая запись `EntryListItem`
(поле `date`, epoch millis) преобразуется в `LocalDate` в системной
зоне устройства и попадает в секцию с соответствующей датой. Секция
с сегодняшней датой SHALL отображаться без заголовка. Заголовок
остальных секций SHALL определяться так: если дата секции совпадает
со вчерашней датой устройства — заголовок «Вчера»; иначе — дата в
формате `dd.MM.yyyy` (день.месяц.год). Заголовок «Вчера» SHALL быть
локализован (ru/en) через строку `entry_section_yesterday` в ресурсах
приложения. Секции SHALL отображаться по убыванию даты: новые сверху.
Внутри одной секции записи SHALL идти по убыванию `date` (epoch
millis) — независимо от порядка входного списка. Удаление записи SHALL
продолжать работать: алерт подтверждения открывается по идентификатору
записи независимо от того, в какой секции она находится.

#### Scenario: Запись сегодняшней даты отображается в начале списка без заголовка

- **WHEN** в списке есть запись с датой `date`, совпадающей с текущей
  датой устройства
- **THEN** запись отображается вверху списка, в секции с сегодняшней
  датой
- **AND** секция не имеет заголовка: текст «Сегодня»/«Today» нигде
  не отображается

#### Scenario: Запись вчерашней даты попадает в секцию с заголовком «Вчера»

- **WHEN** в списке есть запись с датой `date`, совпадающей с датой
  устройства минус один день
- **THEN** запись отображается в секции с заголовком «Вчера»
- **AND** заголовок секции берётся из локализованной строки
  `entry_section_yesterday`

#### Scenario: Запись более ранней даты попадает в секцию с заголовком в формате dd.MM.yyyy

- **WHEN** в списке есть запись с датой `date`, более ранней, чем
  дата устройства минус один день, в системной зоне устройства
- **THEN** запись отображается в секции
- **AND** заголовок секции отображается в формате `dd.MM.yyyy`
  (день.месяц.год) с ведущими нулями в дне и месяце

#### Scenario: Секции идут по убыванию даты

- **WHEN** в списке есть записи с разными календарными датами
- **THEN** секция с более поздней датой отображается выше секции
  с более ранней

#### Scenario: Внутри секции записи идут по убыванию даты/времени

- **WHEN** секция содержит две и более записи одного календарного дня
- **THEN** запись с более поздним временем `date` расположена выше
  записи с более ранним временем той же даты

#### Scenario: Удаление из секции работает

- **WHEN** пользователь выполняет длинное нажатие на строку записи
  внутри секции и подтверждает удаление в алерте
- **THEN** запись удаляется из хранилища
- **AND** запись исчезает из секции; если секция становится пустой —
  секция целиком исчезает из списка
