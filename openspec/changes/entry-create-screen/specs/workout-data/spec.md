# workout-data Дельта

## MODIFIED Requirements

### Requirement: Предзаполнение каталога стандартными упражнениями

**Изменённый текст требования (полностью):**

При первом создании базы данных каталог упражнений SHALL содержать ровно
13 стандартных упражнений с назначенными категориями: подтягивания (PULL),
австралийские подтягивания (PULL), приседания (LEGS), отжимания (PUSH),
отжимания на коленях (PUSH), выпады (LEGS), отжимания на брусьях (PUSH),
планка (CORE), скручивания (CORE), подъёмы ног в висе (CORE), приседания
пистолетиком (LEGS), бег (CARDIO), скакалка (CARDIO). Каждое стандартное
упражнение SHALL иметь тип измерения `measuredBy`: `TIME` — для бега,
планки и скакалки, `REPS` — для остальных десяти. Все стандартные
упражнения SHALL быть помечены как созданные системой (не пользователем).
Названия стандартных упражнений SHALL браться из локализованных строковых
ресурсов. До первого релиза приложения расхождение версий схемы БД
SHALL решаться деструктивно (`fallbackToDestructiveMigration`, база
пересоздаётся с новым prepopulate); с первым релизом деструктивный
фоллбек заменяется миграциями.

#### Scenario: Первый запуск приложения

- **WHEN** база данных создаётся впервые
- **THEN** каталог содержит ровно 13 упражнений, все помечены как стандартные
- **AND** пользовательских упражнений в каталоге нет

#### Scenario: Локализация при prepopulate

- **WHEN** prepopulate выполняется на устройстве с локалью `en`
- **THEN** названия стандартных упражнений записаны английскими строками
- **AND** при локали `ru` — русскими

#### Scenario: Разметка типов измерения при prepopulate

- **WHEN** база данных создаётся впервые
- **THEN** бег, планка и скакалка имеют `measuredBy = TIME`
- **AND** остальные десять стандартных упражнений имеют `measuredBy = REPS`

#### Scenario: Изменение схемы до релиза

- **WHEN** приложение с новой версией схемы открывает базу, созданную
  предыдущей версией
- **THEN** база пересоздаётся деструктивно с новым prepopulate
- **AND** приложение не падает на открытии
