# Spec Delta

## MODIFIED Requirements

### Requirement: Единый каталог для стандартных и пользовательских упражнений

Пользовательские упражнения SHALL сохраняться в тот же каталог, что и
стандартные, с пометкой «создано пользователем». Для создания упражнения
SHALL требоваться название и категория; комментарий SHALL быть опциональным.
Каждое упражнение каталога — стандартное и пользовательское — SHALL иметь
тип измерения `measuredBy` (`REPS` — упражнение на повторы, `TIME` —
упражнение на время); при создании пользовательского упражнения без явного
указания типа SHALL применяться `REPS`. Тип измерения SHALL сохраняться
вместе с упражнением и SHALL быть доступен при чтении каталога.
Идентификатор упражнения SHALL генерироваться системой. Каждое упражнение
каталога SHALL иметь булевый флаг `isArchived` (`false` — упражнение
активно и видно в каталоге; `true` — упражнение скрыто из каталога и
доступно только через экран архива). По умолчанию `isArchived` SHALL быть
`false` (новые и существующие упражнения — активные). В Room-сущности
`ExerciseEntity` поле SHALL храниться как `INTEGER NOT NULL DEFAULT 0`
через `@ColumnInfo(name = "is_archived", defaultValue = "0")`.

#### Scenario: Создание пользовательского упражнения

- **WHEN** пользовательское упражнение «Отжимания на турнике» категории PULL
  с комментарием «широкий хват» сохраняется
- **THEN** оно появляется в каталоге с пометкой «пользовательское»
  AND `isArchived = false` по умолчанию
- **AND** стандартные упражнения остаются неизменными

#### Scenario: Тип измерения по умолчанию при создании

- **WHEN** пользовательское упражнение сохраняется без явного указания
  типа измерения
- **THEN** упражнение сохраняется с `measuredBy = REPS`
  AND `isArchived = false`

#### Scenario: Создание упражнения «на время»

- **WHEN** пользовательское упражнение (например, «стойка на руках»)
  сохраняется с `measuredBy = TIME`
- **THEN** при чтении каталога упражнение возвращается с `measuredBy = TIME`
  AND `isArchived = false`

### Requirement: Опциональный номер иконки упражнения

Каждое упражнение каталога (стандартное и пользовательское) SHALL иметь
опциональный номер иконки `iconNumber`: `null` — иконка не назначена,
целое число — номер в стабильной таблице иконок (1..19, номера не зависят
от имён ресурсов). Значение SHALL сохраняться вместе с упражнением и
SHALL быть доступно при чтении каталога без изменений. По умолчанию
`iconNumber` SHALL быть `null` для новых пользовательских упражнений —
номер назначается только при явном указании (UI выбора иконки — вне
скопа). Prepopulate стандартного набора SHALL назначать номера иконок
всем 13 стандартным упражнениям по фиксированному соответствию
(номер — упражнение): 13 — подтягивания, 14 — австралийские подтягивания,
18 — приседания, 15 — отжимания, 16 — отжимания с колен, 12 — выпады,
7 — брусья, 15 — планка (осознанное переиспользование: отдельной иконки
планки нет, планка попадает в группу push/core-статики), 8 — скручивания,
1 — подъёмы ног в висе, 19 — приседания пистолетиком, 17 — бег,
11 — скакалка. В Room-сущности `ExerciseEntity` поле SHALL храниться
как колонка `icon_number` типа `INTEGER` (nullable) без SQL DEFAULT.
Номер иконки SHALL NOT валидироваться по диапазону в слое данных:
контроль соответствия ресурсам — ответственность UI-слоя, который
рендерит иконку (неизвестный номер — тихий fallback «без иконки»).

#### Scenario: Сохранение и чтение номера иконки

- **WHEN** пользовательское упражнение сохраняется с `iconNumber = 5`
- **THEN** при чтении каталога упражнение возвращается с `iconNumber = 5`

#### Scenario: Упражнение без иконки

- **WHEN** пользовательское упражнение сохраняется без указания
  `iconNumber`
- **THEN** при чтении каталога упражнение возвращается с `iconNumber = null`

#### Scenario: Стандартный набор prepopulate с номерами иконок

- **WHEN** база данных создаётся впервые и стандартный набор предзаполняется
- **THEN** все 13 стандартных упражнений имеют ненулевой `iconNumber`
  согласно фиксированному соответствию, заданному в теле Requirement

#### Scenario: Отсутствие иконки и её наличие различимы

- **WHEN** одно упражнение сохранено с `iconNumber = null`, другое —
  с `iconNumber = 0`
- **THEN** при чтении оба значения различимы: `null` и `0`

## REMOVED Requirements

### Requirement: Предзаполнение каталога стандартными упражнениями

**Reason**: Контракт «до первого релиза расхождение версий SHALL
решаться деструктивно» исполнил своё: перед первым релизом деструктивный
фоллбек убирается (обещание KDoc `WorkoutDatabase` и design.md архивной
задачи 2026-09-17-seed-on-destructive-migration). Сценарии «Изменение
схемы до релиза» и «Деструктивная миграция восстанавливает стандартный
набор» описывают путь, который перестаёт существовать: без
`fallbackToDestructiveMigration` Room бросает исключение до пересоздания
таблиц.

**Migration**: Заменяется требованием «Предзаполнение каталога
и миграции схемы БД» (см. ADDED): контракт
prepopulate (13 стандартных, локализация, `measuredBy`, `iconNumber`)
сохраняется без изменений, изменение схемы БД идёт через миграции.

## ADDED Requirements

### Requirement: Предзаполнение каталога и миграции схемы БД

При первом создании базы данных каталог упражнений SHALL содержать ровно
13 стандартных упражнений с назначенными категориями: подтягивания (PULL),
австралийские подтягивания (PULL), приседания (LEGS), отжимания (PUSH),
отжимания на коленях (PUSH), выпады (LEGS), отжимания на брусьях (PUSH),
планка (CORE), скручивания (CORE), подъёмы ног в висе (CORE), приседания
пистолетиком (LEGS), бег (CARDIO), скакалка (CARDIO). Каждое стандартное
упражнение SHALL иметь тип измерения `measuredBy`: `TIME` — для бега,
планки и скакалки, `REPS` — для остальных десяти. Все стандартные
упражнения SHALL быть помечены как созданные системой (не пользователем).
Названия стандартных упражнений SHALL браться из локализованных
строковых ресурсов. Изменения схемы БД SHALL решаться миграцией:
при расхождении версии файла БД с версией схемы и отсутствии
зарегистрированной миграции (`addMigrations(...)`) Room SHALL бросать
исключение при открытии базы; деструктивный фоллбек
(`fallbackToDestructiveMigration`) SHALL NOT использоваться.

#### Scenario: Первый запуск приложения

- **WHEN** база данных создаётся впервые
- **THEN** каталог содержит ровно 13 упражнений, все помечены как стандартные
- **AND** пользовательских упражнений в каталоге нет

#### Scenario: Локализация при prepopulate

- **WHEN** prepopulate выполняется на устройстве с локалью `en`
- **THEN** названия стандартных упражнений записаны английскими строками
- **AND** при локали `ru` — русскими

#### Scenario: Разметка типов измерения при prepopulate

- **WHEN** база данных создаётся впервые
- **THEN** бег, планка и скакалка имеют `measuredBy = TIME`
- **AND** остальные десять стандартных упражнений имеют `measuredBy = REPS`

#### Scenario: Изменение схемы без миграции отклоняется

- **WHEN** приложение с новой версией схемы открывает базу, созданную
  предыдущей версией, и подходящая миграция не зарегистрирована
- **THEN** открытие базы завершается исключением (`IllegalStateException`)
- **AND** файл базы не пересоздаётся: `user_version` и существующие
  данные остаются в исходном состоянии
