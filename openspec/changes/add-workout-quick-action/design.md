# Design

## Context

См. proposal.md (Why). Текущее состояние кода (проверено):

- FAB главного экрана выполняет `navController.navigate(Screen.EntryCreate.createRoute())` — `ui/screens/root/NavDestinations.kt:49`.
- Маршрут: `navigation/Screen.kt:81` — `entry_create?entryId={entryId}`, `createRoute() = entry_create?entryId=-1`.
- Destination регистрируется в `ui/screens/root/RootScreen.kt:187`, VM-фабрика — `RootScreen.kt:261-281`.
- `MainActivity.kt` не читает Intent (нет `getIntent`/`onNewIntent`), `launchMode` не задан (standard).
- `app/src/main/AndroidManifest.xml`: у MainActivity только intent-filter MAIN/LAUNCHER.
- Подпись шортката: строка `add_workout` = «Добавить тренировку» / «Add workout» (уже есть в ru/en).
- Иконка приложения — adaptive `@mipmap/ic_launcher`; для шортката не используется.
- Аналитика: `UserActionType.OPEN_ENTRY_CREATE` в `analytics/AnalyticsEvent.kt` существует; сейчас логируется только при нажатии FAB (`ui/screens/main/MainScreen.kt:122-123`).
- minSdk = 26, targetSdk = 37, applicationId = `com.myworkouts`; ShortcutManager/shortcuts.xml/deep links в репо отсутствуют.
- Экран создания записи поддерживает режим редактирования (`entryId != -1`) и подтверждение закрытия при несохранённых изменениях — дублирование экрана поверх себя недопустимо и заметно пользователю.

## Goals / Non-Goals

**Goals:**

- Статический шорткат лаунчера «Добавить тренировку», видимый сразу после установки, без иконки.
- Открытие экрана создания записи из любого состояния приложения (холодный старт, свёрнутое приложение, любой текущий экран).
- Один экземпляр Activity и один экземпляр экрана создания записи (в том числе когда он уже открыт).
- Back stack: main → entry_create; стартовый маршрут графа не меняется.
- Аналитика шорткат-пути существующим событием.

**Non-Goals:**

- Динамические шорткаты, pinned-шорткаты, другие быстрые действия (просмотр статистики и т.п.).
- Deep links (http/https), App Links.
- Иконка для шортката (никаких новых drawable).
- Изменение существующих строковых ресурсов и поведения FAB.

## Decisions

### D1. Статический шорткат (res/xml/shortcuts.xml), не динамический

Статический шорткат объявляется в `app/src/main/res/xml/shortcuts.xml` и подключается meta-data `android.app.shortcuts` у MainActivity. Он виден в лаунчере сразу после установки без какого-либо кода публикации.
Альтернатива (отклонена): динамический `ShortcutManager` — требует триггера публикации в рантайме, добавляет состояние и код ради действия, известного на этапе сборки.

### D2. Собственный action + отдельный intent-filter у MainActivity

Action шортката — `com.myworkouts.action.ADD_WORKOUT`; у MainActivity добавляется intent-filter с этим action и `category="android.intent.category.DEFAULT"` (статические шорткаты отправляют intent с этим category; без intent-filter платформа не стартует шорткат).
Альтернатива (отклонена): переиспользовать MAIN/LAUNCHER intent-filter или фильтровать по extra — MAIN/LAUNCHER запускается тапом по иконке с другим semantics, а extras в фильтрах не различаются; собственный action делает источник запуска однозначным и проверяемым.

### D3. `android:launchMode="singleTop"` + обработка `onNewIntent`

MainActivity переключается на `launchMode="singleTop"`. Intent шортката обрабатывается в двух точках: `onCreate` — только при первом создании (`savedInstanceState == null`; при пересоздании после поворота/смены темы платформа доставляет тот же launch-intent повторно, разбирать его нельзя) — и `onNewIntent` (activity уже наверху стека — свёрнутое приложение, любой текущий экран внутри Compose-навигации). Неизвестные action игнорируются — поведение при обычном запуске не меняется.
Альтернатива (отклонена): оставить `standard` — каждый запуск шортката создаёт второй экземпляр Activity поверх старого, «назад» ведёт в предыдущую Activity с её состоянием, дублируя back stack. `singleTask`/`singleInstance` (отклонены) — избыточная перестройка launch-семантики всего приложения ради одного действия.

### D4. Стартовый маршрут NavHost не меняется; запрос навигации выполняется после построения графа

`startDestination` остаётся `Screen.Main.route`. MainActivity не знает про навигацию: она лишь фиксирует одноразовый запрос «открыть создание записи» (state-флаг/flow). RootScreen после построения графа (`LaunchedEffect`) читает запрос и выполняет `navigate(Screen.EntryCreate.createRoute()) { launchSingleTop = true }`. Back stack получается main → entry_create — идентично FAB, требование спеки tab-navigation про start destination остаётся валидным.
Альтернатива (отклонена): менять startDestination по intent — ломает back stack («назад» закрывает приложение вместо главного экрана), дублирует точку входа в граф и нарушает существующее требование.

### D5. Не открывать второй экран создания записи поверх уже открытого

Guard в точке выполнения запроса навигации: если текущий destination графа уже `entry_create` (пользователь сидел на форме, свернул приложение, нажал шорткат — приходит `onNewIntent`), навигация не выполняется — открытая форма с её несохранённым вводом остаётся как есть. Плюс `launchSingleTop = true` на всякий случай для прочих путей. Проверка выполняется по маршруту destination, а не по флагу Activity, потому что экран живёт внутри одного Activity.
Альтернатива (отклонена): всегда выполнять navigate — поверх формы с несохранённым вводом открывается её чистая копия, теряется контекст пользователя и раздувается back stack.

### D6. Шорткат без иконки; подпись — существующая строка `add_workout`

В `shortcuts.xml` атрибут `android:icon` не задаётся вовсе; `android:shortcutShortLabel` — `@string/add_workout`. Новых строк и drawable не заводим.
Альтернативы (отклонены): переиспользовать `@mipmap/ic_launcher` — это иконка приложения, а не действия; собственный вектор «+» — не запрашивалось, отдельный ресурс ради одного пункта. Подпись обязательна (без неё платформа отклоняет шорткат) — берём готовую строку.

### D7. Аналитика — существующее `OPEN_ENTRY_CREATE`

В точке выполнения запроса навигации (RootScreen, шорткат-путь) логируется `AnalyticsEvent.UserAction(UserActionType.OPEN_ENTRY_CREATE)` — тот же event, что у FAB. Новых enum-значений нет; FAB-путь не дублируется (событие логирует только шорткат-путь в своей точке).
Альтернатива (отклонена): новый `UserActionType` для источника шортката — не запрашивалось, спека требует существующее событие.

### D8. Тесты

- JVM: чистая функция разбора «action intent → запрос открытия создания записи» (`android.intent.action.*`, null, наш action) — TDD: сначала падающий тест.
- androidTest: `ActivityScenario` с intent шортката — холодный старт открывает экран «Новая запись»; повторная доставка intent при открытой форме не дублирует экран; «назад» → главный экран; пересоздание Activity (поворот) после закрытия формы не возвращает на форму; `ShortcutManager.getStaticShortcuts()` содержит `add_workout` без иконки (API доступен с minSdk 26).
- Манифест/ресурсы проверяются фактом (androidTest + ручная проверка в лаунчере эмулятора), моков манифеста нет.

## Risks / Trade-offs

- [Не все лаунчеры показывают статические шорткаты] → Поведение вне контроля приложения; спека требует объявления, проверка в дефолтном лаунчере эмулятора.
- [Лаунчер может подставить иконку приложения как fallback для пункта без иконки] → Это поведение лаунчера, не приложения; в требованиях не меняем, фиксируем факт при ручной проверке.
- [Лаунчер отображает до ~4 шорткатов суммарно (статические + динамические), отрисовка и наличие пункта зависят от лаунчера] → Один шорткат в лимит укладывается; поведение вне контроля приложения — проверка в дефолтном лаунчере эмулятора (задача 4.1).
- [`singleTop` меняет поведение обычного запуска (тап по иконке при открытой Activity теперь идёт в `onNewIntent`)] → Обработчик игнорирует чужие action, визуальное поведение не меняется; покрывается существующими UI-тестами полного прогона.
- [Пересоздание Activity (поворот, смена темы) повторно доставляет launch-intent в `onCreate`] → Intent разбирается только при `savedInstanceState == null`; androidTest-сценарий: после закрытия формы пересоздание не возвращает на неё.
- [Состояние формы при повторном шорткате сохраняется (не сбрасывается)] → Осознанный выбор: несохранённый ввод пользователя не теряется.
