# Spec Delta

## Purpose

Быстрый доступ к созданию записи о тренировке через меню долгого нажатия на иконку приложения: статический шорткат лаунчера открывает экран создания записи из любого состояния приложения, с корректным back stack и без дублирования уже открытого экрана.

## ADDED Requirements

### Requirement: Статический шорткат «Добавить тренировку» объявлен для лаунчера

Приложение SHALL объявлять статический шорткат с идентификатором `add_workout` для отображения в меню долгого нажатия на иконку приложения. Подпись шортката SHALL браться из существующей локализованной строки `add_workout`; собственной иконки у шортката SHALL NOT быть — атрибут иконки не задаётся, пункт меню отображается текстом. Intent шортката SHALL содержать собственный action, на который у главной Activity SHALL быть объявлен intent-filter.

#### Scenario: Шорткат доступен лаунчеру
- **WHEN** лаунчер запрашивает шорткаты приложения
- **THEN** статический шорткат `add_workout` присутствует в списке
- **AND** у него задана подпись
- **AND** собственной иконки у него нет

#### Scenario: Подпись локализована
- **WHEN** лаунчер отображает пункт шортката
- **THEN** подпись берётся из строки `add_workout` (ru «Добавить тренировку» / en «Add workout»)

#### Scenario: Intent шортката запускает главную Activity
- **WHEN** лаунчер запускает шорткат
- **THEN** главная Activity получает intent с action этого шортката

### Requirement: Выбор шортката открывает экран создания записи

Запуск приложения через шорткат SHALL открывать экран создания записи о выполнении — тот же экран, что открывается по кнопке создания на главном экране, — из любого состояния приложения: при холодном старте и при уже запущенном приложении. Второй экземпляр главной Activity при этом SHALL NOT создаваться.

#### Scenario: Холодный старт по шорткату
- **WHEN** приложение не запущено и пользователь выбирает шорткат
- **THEN** приложение открывается сразу на экране «Новая запись»

#### Scenario: Приложение уже запущено на другом экране
- **WHEN** приложение запущено и находится на любом экране, кроме экрана создания записи, и пользователь выбирает шорткат
- **THEN** пользователь оказывается на экране «Новая запись»
- **AND** новый экземпляр Activity не создаётся

#### Scenario: Экран создания записи уже открыт
- **WHEN** пользователь находится на экране «Новая запись», сворачивает приложение и выбирает шорткат
- **THEN** остаётся открытым тот же экран «Новая запись»
- **AND** ещё один такой же экран поверх него не открывается

### Requirement: Возврат из формы открывает главный экран

При закрытии экрана создания записи, открытого через шорткат, действие «назад» SHALL возвращать на главный экран приложения, как при открытии формы по кнопке создания.

#### Scenario: Назад из формы, открытой по шорткату
- **WHEN** пользователь закрывает экран «Новая запись», открытый через шорткат
- **THEN** отображается главный экран
- **AND** back stack содержит главный экран под экраном создания записи

### Requirement: Переход на экран создания записи выполняется навигацией

При запуске через шорткат переход на экран создания записи SHALL выполняться навигационным переходом после построения навигационного графа, а не подменой начального маршрута; инвариант начального маршрута остаётся за капабилити tab-navigation.

#### Scenario: Back stack при запуске через шорткат
- **WHEN** приложение стартует по шорткату
- **THEN** экран создания записи открыт навигационным переходом после построения графа
- **AND** back stack содержит главный экран под экраном создания записи

### Requirement: Открытие по шорткату попадает в аналитику

Переход на экран создания записи по шорткату SHALL логироваться существующим событием пользовательского действия «открытие экрана создания записи» — тем же, что используется при нажатии кнопки создания на главном экране.

#### Scenario: Аналитика шорткат-пути
- **WHEN** экран создания записи открыт через шорткат
- **THEN** логируется событие пользовательского действия «открытие экрана создания записи»
- **AND** новые типы событий для этого не вводятся
